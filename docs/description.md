测试用例管理与执行软件 —— 软件需求说明书（按已实现功能整理）

项目名称：测试用例管理与执行软件
开发技术：Python + PyQt5
架构原则：UI 页面文件（.ui）与业务代码完全分离，通过 QtUiLoader 动态加载
运行要求：支持 7×24 小时长时间稳定运行；QT 多线程 + Python 线程池的异步任务机制；界面无阻塞、不卡顿；全链路异常捕获与错误处理，任何异常不导致程序退出

一、总体功能概述

软件分为三大核心业务页面：
        执行页面、管理页面、系统设置页面；
配套用户权限体系、全局变量管理、五类测试用例引擎、HTML 报告与运行日志方案。
管理页面内左侧边导航集成 ：测试计划、全局变量、系统设置、用户管理 四个子页面。



二、用户权限管理与权限分级模块

1. 用户角色
- 管理员：拥有全部功能权限，可访问执行页面、管理页面（含变量/设置/用户子页），支持测试计划增删改查、变量编辑、清零统计等所有操作
- 操作员：仅允许进入【执行页面】，无法访问管理页面、系统设置页面，不能编辑测试计划与全局变量；执行页面顶部的"管理页面"按钮仅管理员可见

2. 基础账号功能：用户新增、删除、修改账号、修改密码、修改角色、备注

3. 登录校验：启动时强制登录，权限动态控制菜单/页面入口可见性；角色校验为账号绑定角色（管理员/操作员）

4. 一键分权（require_login）：默认不开启；开启后下一次启动软件启用登录页面，不开启则直接进入管理页面（默认管理员会话）


三、【执行页面】（操作员可见核心页面）

3.1 基础操作

1. 选择测试计划：点击计划路径输入框弹出可选计划菜单（自动扫描 data/plans/ 及当前计划目录下的 .plan/.json 文件），或浏览其他位置加载
2. 控制按钮：开始执行、暂停执行/继续、停止；支持中途暂停、恢复、停止
3. 执行状态显示：总体结果大字显示（PASS/FAIL/执行中/已停止），颜色区分明显，长时间保持直到下一次执行
4. 树形列表：测试步骤以"序列 → 用例"树形展示，可展开/收起，实时展示每条用例运行状态（待执行/运行中/PASS/FAIL/跳过/超时）与耗时；Loop 类型用例的每组 session 以子节点平铺展示结果

3.2 日志面板

- 默认隐藏执行日志
- 【日志】切换按钮：点击展开/收起实时运行日志；提供清空按钮；运行日志同时实时写入 .log 文件

3.3 生产统计看板

实时展示数据：
- 当前 SN 码（由脚本通过 set_sn_to_Panel 上报，页面只读展示）
- 当前批次、测试节拍
- 总测试数量、良品数量、不良数量、良率、不良率（按天统计，存于 data/stats.ini）
- 清零按钮：点击弹窗要求输入密码；初始密码固定 0000（可在全局设置修改）；密码校验通过后方可清空统计数据
- 跨天自动切换统计日期

3.4 机器人状态栏

- 周期性刷新并展示机器人温度/电流/电压/电池状态；数值可空显示 "--"
- 脚本可通过内置 API 更新（set_robot_*），并随运行日志、HTML 报告汇总输出

3.5 UI 性能约束

所有测试任务在后台线程异步执行，禁止主线程阻塞，界面操作持续响应；页面操作通过"_guarded"包装，异常写入系统日志并弹窗提示，不导致崩溃

3.6 执行模式

- 正常执行（执行页面）：点击"开始"执行一轮测试，自动加载计划内全局变量，SN 由脚本填入；结果计入生产统计并生成报告
- 调试执行（管理页面）：在管理页面内弹出调试窗口执行当前计划，结果不入生产统计
- 连续执行：引擎预留 wait_sn/continuous 机制；正常执行单次一轮（生产连续模式后续按需启用）

四、【管理页面】（仅管理员可访问）

核心功能：测试计划（PLAN）新增、编辑、删除、保存、另存为；每个 PLAN 独立 .plan 文件持久化（JSON 格式，存于 data/plans/，支持子目录分类）。

层级结构：测试PLAN → 多个测试序列 → 每个序列包含多条测试用例

4.1 层级结构定义

1. 测试PLAN（测试方案）：名称、描述、全局变量（随计划保存）、计划级设置、序列列表
2. 测试序列：一个 PLAN 可新增多条序列，支持增删、修改序列名称
3. 测试用例：一条序列下可添加多条用例（支持右键复制/粘贴用例）

4.2 测试PLAN 全局存储策略（每计划独立配置）

每条测试计划独立配置，通过"计划设置"弹窗编辑：

- 存储模式：local（本地存储）/ remote（远程 MES 上报）
- 批次名称、日志目录、报告目录
- 远程文件存储：启用后把 HTML 报告与日志文件以 multipart 上传到指定服务器地址
- 逐用例 JSON 上报：启用后按用例逐条上报（含普通用例、测量项、Loop 子项列表）；可配置上报地址、上报密钥
- MES 服务器地址、交互接口
- 服务器用户名/密码（HTTP 基本认证，用于远程上报鉴权）
- 兼容预留：远程文件服务器、远程数据库 IP/表名

4.3 单条测试用例通用配置项（所有类型共用）

1. 执行超时时间（单位 ms）；支持设置 -1 代表无限等待
2. 失败重试次数（0~10）
3. 失败策略二选一：失败后暂停执行 / 失败继续执行下一条用例
4. 跳过此用例（不执行，报告中标记为跳过）
5. 用例描述
6. 选择执行类型（5 大类：Action / Delay / Pop / Measurement / Loop），每种类型对应独立动态表单

4.4 五类执行类型详细定义

（1）Action 类型

- 用途：仅执行指定函数，不校验返回结果
- 页面配置项：脚本文件路径、目标函数名称、描述
- 报告输出：记录执行函数名称、执行类型，不做结果判定
- 扩展：函数返回 dict 时视为该用例的结构化结果（如标定参数），随 HTML 报告以参数表展示，并随逐用例 JSON 上报

（2）Delay 延时类型

- ms 级精确延时，遵守暂停/停止指令
- 配置项：延时时长（可切换 ms/s/min 单位）、说明
- 报告记录：实际执行耗时；全局"速度系数"可对延时统一缩放

（3）Pop 人机交互弹窗类型

- 配置自定义弹窗标题、展示文本（文本长度无限制）、确认/取消按钮文字
- 返回值：True / False；可绑定到全局变量供后续步骤逻辑使用
- 弹窗请求通过信号桥接回 GUI 线程，避免在工作线程操作界面

（4）Measurement 测量执行类型

1. 自定义展示文本
2. 选择外部脚本路径，自动解析脚本内所有公开函数并下拉选择
3. 选中函数后，自动读取函数签名（参数、默认值、类型注解推断）加载入参列表
4. 参数、返回值自动识别类型：int / str / float / list / dict
5. 入参来源可切换：固定值 / 全局变量（执行时替换为变量当前值），有增加/删除 按钮功能
6. 返回值支持绑定系统全局变量，执行完成自动赋值，有增加/删除 按钮功能
7. 支持对返回值逐项判定：取值项(item，支持 dict 点号路径与 list 下标)、判定方式（等于/不等于/大于/小于/范围内/包含/长度）、判定阈值
8. 阈值写法："100"单值等于、"20~30"范围、"100"配合"大于/小于"

（5）Loop 循环批量测试类型

- 适用场景：同一函数、同一测试逻辑，批量多组测试数据循环执行
- 配置项：
- YAML 数据文件路径（可指定 session 键名，默认 "sessions"；支持键名容错匹配及 sessions/items/data/tests/cases 回退）
- 测试脚本路径，自动读取可选函数名称（含可选解析函数 parser）
- 阈值覆盖（overrides）：页面配置优先覆盖 YAML 内的期望阈值，支持 str/int/float/list/dict 类型转换
- 执行规则：
1. 加载 YAML 中每组 session 数据循环执行目标函数；支持包装式{name,input,expected}与扁平式两种数据格式
2. 按函数签名自适应传参（关键字匹配、整体 dict、无参等）
3. 阈值、判定规则优先读取页面配置；页面无配置则使用 YAML 内部定义；无期望时自动从返回值中的 pass/ok/result 状态字段判定
4. 支持脚本通过 set_measure_result 自描述测量结果（value/expected/unit/upper/lower/message/pass）合并进会话结果
- 页面展示：循环所有测试结果以子节点平铺展示（PASS/FAIL + 判定详情）
- HTML 报告：完整输出每一组 session 测试数据（序号、名称、输入、期望、实际、判定、结果）

4.5 用例编辑弹窗

- 上方为通用配置区（名称、类型、超时、重试、失败策略、跳过、描述）
- 下方为类型专用表单（QStackedWidget 按类型切换），五种类型各自加载独立 .ui 文件
- 对滚轮误改值做防护（未聚焦的下拉/数值控件滚轮改为滚动表单）

五、全局变量管理模块（管理员权限）

管理页面侧边栏"全局变量"子页：

- 变量：新增、删除、修改、查询；数据类型可选 int / str / float / list / dict（list/dict 支持 JSON 文本导入）
- 变量全局作用域：可供所有测试用例读取、赋值（Measurement 返回绑定、Pop 结果绑定、脚本 API 均可使用）
- 变量随测试计划保存：打开/保存计划时整体替换/回写（plan.variables），保证计划可移植；旧版 variables.json 仅作启动初始种子
- 使用方式在"帮助"中说明（含内置 API 函数）

六、系统【设置页面】（全局基础设置，管理员）

管理页面侧边栏"系统设置"子页，全局软件基础参数：

1. UI 界面字体大小调整
2. 主窗口默认尺寸设置
3. 测试整体执行速度调节（延时系数统一缩放，预留调速接口）
4. 统计清零密码（默认 0000）
5. 工位 ID、工位名称（同步显示在执行页顶部标题并对接上报）

七、管理页面附加功能

1. 左侧导航：测试计划 / 全局变量 / 系统设置 / 用户管理
2. 【执行】调试按钮：在管理页面内弹出调试窗口执行当前测试计划，结果不入生产统计
3. 【切换执行页面】按钮：切换到执行页面窗口
4. 【帮助】按钮：弹出帮助对话框，说明全局变量、内置 API 等使用方式
5. 自绘无边框窗口标题栏（最小化/最大化还原/关闭）

八、内置 API 函数（test_api，注入到测试脚本命名空间，可通过 import test_api 使用）

脚本内可直接调用，用于与软件交互：

1. set_sn_to_Panel(sn)：将 SN 传给软件，显示到执行页面并写入报告/日志
2. get_sn()：获取当前 SN（页面/脚本设定的 SN）
3. get_test_result() / get_last_test_result() / get_last_test_detail()：获取当前/上一个用例结果与详情
4. get_display_info(key) / set_display_info(key, value)：执行页面显示信息的读写
5. log(msg)：向运行日志与页面输出脚本日志
6. get_variable(name) / set_variable(name, value)：读写全局变量
7. set_robot_status / set_robot_temperature / set_robot_current / set_robot_voltage / set_robot_battery / get_robot_status：机器人状态栏更新
8. set_measure_result(value, expected, unit, upper, lower, message, passed) / set_measure_value / set_measure_expected / set_measure_range / set_measure_message / set_measure_field / get_measure_result / get_measure_value / get_measure_expected / get_measure_range / get_measure_message / reset_measure_result：Loop 会话的测量结果自描述与读取
9. set_upload_key(key) / get_upload_key()：逐用例 JSON 上报密钥（脚本获取后回填，与上报 key 字段关联）
10. get_station_id() / get_station_name()：取当前工位 ID / 工位名称

脚本加载机制：动态加载 .py，按修改时间缓存；脚本及第三方包搜索路径包含 scripts/ 与 data/ext_packages/（可随时放置第三方包，无需重新打包）；加载失败原因写入运行日志并在 UI 提示。

九、报告、日志与统计

1. 运行日志（RunLogger）：每次运行实时写入 .log 文件（时间戳+级别），涵盖运行环境、执行进度、函数输入输出、判定结果、异常堆栈、硬件状态等
2. HTML 报告：运行结束生成，包含计划名、SN、生成时间、总体结果、总用例/通过/失败/跳过统计；表格逐条展示用例（序号、名称、类型、详情、状态、耗时）；嵌套展示 Action 结构化结果参数表、Loop session 明细
3. 输出位置：默认 data/logs/、data/reports/（计划可配置 log_dir/report_dir）；本地仅保留当天报告与日志，自动清理过期文件
4. 数据上报（按计划设置）：
- MES 远程上报：POST JSON（计划名、SN、工位、总体结果、统计、结果明细）
- 远程文件存储：multipart 上传 HTML 报告与日志
- 逐用例 JSON 上报：一轮一 SN 一密钥一次 POST，records 列表逐条；Loop 用例含父节点+list 子项，测量项含实测值与阈值上下限，标定数据扁平化展开
5. 生产统计：按天写入 data/stats.ini（total/pass/fail），跨天自动切换

十、底层技术架构非功能需求

1. 代码规范
UI 界面(.ui)文件与业务逻辑代码彻底分离，通过 QtUiLoader 加载 ui 文件，禁止业务逻辑写在 UI 定义内
2. 并发架构
- Qt 主线程负责 UI 渲染
- 测试任务使用 QThread(EngineWorker) + Python 线程池(max_workers=4) 异步封装
- 严格禁止在工作线程直接操作 UI 控件，通过信号槽通信；Pop 弹窗通过"信号 + threading.Event 握手"桥接回主线程
- 暂停/停止通过 threading.Event 协作，随时可中断等待中的用例
3. 稳定性
- 面向 7×24 长时间不间断运行；内存泄漏防范（线程池 shutdown、日志句柄关闭）
- 所有外部函数调用、脚本执行、网络请求、文件读写均有 try-except 捕获
- 全局异常钩子（sys.excepthook / Qt message handler / 线程 excepthook）统一收集异常到系统日志（data/logs/），不会造成程序崩溃
- 页面回调以 _guarded 包装，异常弹窗提示但不退出
4. 界面体验
后台任务运行时界面无卡死、无冻结；暂停/启停操作实时响应；Fusion 风格 + 无边框自绘标题栏
