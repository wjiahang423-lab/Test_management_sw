# EOL 测试用例管理与执行软件 —— 部署文档

版本：1.0  
日期：2026-09-15  
适用对象：系统管理员、产线部署工程师

---

## 1. 文档说明

本文档指导如何将「EOL 测试用例管理与执行软件」部署到产线电脑、树莓派、RK3588/Jetson 等目标设备上，包括本地安装、打包分发、远程部署和开机自启动配置。

---

## 2. 系统要求

### 2.1 硬件要求

| 项目 | 最低要求 | 推荐配置 |
|------|---------|---------|
| CPU | 双核 1GHz | 四核 2GHz+ |
| 内存 | 2GB | 4GB+ |
| 磁盘 | 500MB 可用空间 | 2GB+（含报告/日志） |
| 显示 | 1024x768 | 1280x800+ |
| 接口 | USB（扫码枪）| USB + 串口 + CAN |

### 2.2 软件环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（Ubuntu 20.04+、Debian 11+、Raspberry Pi OS）、Windows 10+ |
| Python | 3.8+（推荐 3.10，源码运行必须） |
| 图形环境 | X11/Wayland（Linux）、Windows 桌面（打包后无需 Python） |

### 2.3 依赖清单

| 依赖包 | 版本 | 用途 | 安装方式 |
|--------|------|------|---------|
| PyQt5 | >=5.15 | GUI 框架 | pip / apt |
| PyYAML | >=5.1 | YAML 数据解析 | pip / apt |
| requests | >=2.20 | HTTP 远程上报 | pip |
| paramiko | >=3.0 | SSH/SFTP 远程部署 | pip |
| PyInstaller | 最新 | 打包分发（仅打包机需要） | pip |

## 3. 部署方式总览

软件支持三种部署方式，根据目标设备情况选择：

| 方式 | 适用场景 | 是否需要 Python | 特点 |
|------|---------|----------------|------|
| **源码运行** | 开发调试、树莓派 | 是 | 最灵活，便于修改 |
| **打包分发（onedir）** | 产线电脑、平板 | 否 | 自包含，拷贝即用 |
| **远程推送部署** | 远程树莓派/RK3588 | 自动处理 | 一键推送+自动安装 |

---

## 4. 方式一：源码安装运行

适用于开发环境或目标设备有 Python 环境的场景。

### 4.1 安装 Python（Linux）

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install python3 python3-pip python3-venv

# 验证版本（需 3.8+）
python3 --version
```

### 4.2 获取源码

```bash
# 方式A：Git 克隆
git clone <仓库地址> Test_management_sw
cd Test_management_sw

# 方式B：拷贝源码目录到目标设备
scp -r Test_management_sw user@target:/home/user/
```

### 4.3 安装依赖

```bash
cd Test_management_sw

# 推荐使用虚拟环境
python3 -m venv venv
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

依赖清单（`requirements.txt`）：

```
PyQt5>=5.15
PyYAML>=5.1
requests>=2.20
paramiko>=3.0
```

### 4.4 启动软件

```bash
python3 main.py
```

### 4.5 Linux 图形环境问题

若目标设备无图形界面（如纯命令行 Linux），需安装：

```bash
# 安装虚拟显示
sudo apt install xvfb

# 以虚拟显示启动
Xvfb :99 -screen 0 1280x800x24 &
export DISPLAY=:99
python3 main.py
```

## 5. 方式二：打包分发（产线电脑/平板）

将软件打包为独立程序，目标设备无需安装 Python。

### 5.1 在打包机上打包

打包机需安装 Python 3.8+ 和依赖：

```bash
cd Test_management_sw

# 安装 PyInstaller
pip install pyinstaller

# 执行打包（推荐）
python3 build_app.py

# 或使用 spec 文件（等价）
pyinstaller EOL.spec
```

### 5.2 打包产物

打包完成后生成 `dist/EOL/` 目录：

```
dist/EOL/
├── EOL                          # Linux 主程序
├── EOL.exe                      # Windows 主程序（Windows 下）
├── _internal/                   # 内置代码、UI、脚本、资源（只读）
│   ├── app/                     # 程序代码
│   ├── UI/                      # 界面文件
│   ├── scripts/                 # 示例脚本
│   └── assets/                  # Logo/图标
└── data/                        # 运行数据（可读写，升级不覆盖）
    ├── plans/                   # 测试计划文件
    ├── logs/                    # 运行日志
    ├── reports/                 # HTML 报告
    ├── ext_packages/            # 外部扩展包目录
    ├── users.json               # 用户账号
    ├── settings.json            # 系统设置
    └── variables.json           # 全局变量
```

### 5.3 部署到目标设备

只需拷贝整个 `dist/EOL/` 目录到目标设备：

```bash
# Linux 间拷贝
scp -r dist/EOL/ user@target:/opt/eol/

# 或 U 盘拷贝（Windows/Linux 互通）
cp -r dist/EOL/ /mnt/usb/
```

### 5.4 目标设备启动

```bash
cd /opt/eol
./EOL          # Linux
# 或双击 EOL.exe  # Windows
```

### 5.5 注意事项

- 打包不可跨架构交叉编译（x86 打的包不能在 ARM 上运行）
- `data/` 目录与主程序同级，升级/重新打包不会覆盖
- 跨电脑迁移只需拷贝整个 `dist/EOL/` 文件夹

## 6. 方式三：远程推送部署（树莓派/RK3588）

通过 SSH 一键推送源码到远程设备并自动部署。

### 6.1 前提条件

- 开发机已安装 `sshpass`：`sudo apt install sshpass`
- 远程设备已开启 SSH 服务
- 远程设备网络可达

### 6.2 一键推送部署

```bash
cd Test_management_sw/deploy

# 方式A：推送源码 + 在目标机打包（推荐，适用于树莓派ARM架构）
./push_source_to_pi.sh <IP> <用户名> <密码> on onedir

# 方式B：推送源码 + 直接源码运行（用系统Python）
./push_source_to_pi.sh <IP> <用户名> <密码> on source
```

参数说明：

| 参数 | 位置 | 默认值 | 说明 |
|------|------|--------|------|
| IP | 第1个 | 10.5.35.49 | 远程设备 IP |
| 用户名 | 第2个 | pi | SSH 用户名 |
| 密码 | 第3个 | raspberry | SSH 密码 |
| 开机自启 | 第4个 | on | on=开启，off=关闭 |
| 部署模式 | 第5个 | onedir | onedir=打包运行，source=源码运行 |

示例：

```bash
# 部署到树莓派，开启开机自启，使用打包方式
./push_source_to_pi.sh 10.5.35.49 wangbo MyPassword on onedir

# 部署到 RK3588，关闭开机自启，使用源码方式
./push_source_to_pi.sh 192.168.1.100 root root off source
```

### 6.3 部署流程说明

**onedir 模式流程：**
1. 开发机打包源码为 tar.gz
2. 通过 SCP 推送到远程设备 `/tmp/`
3. 远程设备解压到 `~/eol_source/`
4. 远程设备安装 apt 依赖（python3-pyqt5 等）
5. 远程设备用 PyInstaller 本机打包
6. 配置 systemd 服务实现开机自启

**source 模式流程：**
1. 开发机打包源码为 tar.gz
2. 通过 SCP 推送到远程设备
3. 远程设备用 apt 安装系统级依赖
4. 配置 systemd 服务开机自启

### 6.4 验证部署

```bash
# SSH 到远程设备
ssh user@target

# 检查服务状态
systemctl status eol-cit.service     # 应显示 active (running)
systemctl is-enabled eol-cit.service # 应显示 enabled

# 查看日志
journalctl -u eol-cit.service -n 50

# 手动启动测试
# onedir 模式
~/eol_source/deploy/dist/EOL_CIT/EOL_CIT

# source 模式
python3 ~/eol_source/main.py
```

### 6.5 开机自启说明

- 部署脚本默认开启开机自启，通过 systemd 服务 `eol-cit.service` 实现
- 服务随图形会话启动
- `data/users.json` 中 `require_login=false` 时，开机后直接进入主界面无需登录
- 关闭自启：部署脚本参数传 `off`

## 7. 外部扩展包安装

测试脚本可能用到第三方库（如 paramiko、pyserial、numpy），软件提供扩展包机制，无需重新打包。

### 7.1 机制说明

- 软件启动时自动将 `data/ext_packages/` 加入脚本的 `sys.path`
- 放在此目录下的任何 Python 包都可被脚本导入
- 位于可写的 `data/` 下，与只读的 `_internal/` 隔离
- 升级软件不会清掉扩展包

### 7.2 安装步骤

**在联网电脑上准备扩展包：**

```bash
# 方式一：下载 whl 文件（推荐）
pip download --only-binary=:all: --platform <平台> -d <下载目录> pyserial

# 方式二：安装到临时目录
pip install --target <临时目录> pyserial numpy
```

平台标识：

| 目标设备 | 平台标识 |
|---------|---------|
| Windows x64 | `win_amd64` |
| Linux x64 | `manylinux2014_x86_64` |
| Linux ARM64（RK3588/Jetson） | `linux_aarch64` |
| 树莓派（32位 OS） | `linux_armv7l` |

**拷贝到目标设备：**

```bash
# U 盘/网络拷贝到
dist/EOL/data/ext_packages/
# 或者在目标机直接联网安装
cd dist/EOL/data/ext_packages/
pip install --target . pyserial numpy
```

### 7.3 验证

重启软件后执行相关测试脚本，若仍有导入错误，查看系统日志：

```bash
cat data/logs/system_$(date +%Y%m%d).log | grep -i import
```

## 8. 配置说明

### 8.1 首次启动配置

软件首次启动会自动创建以下文件：

| 文件 | 说明 |
|------|------|
| `data/users.json` | 默认账号 admin/admin、operator/operator |
| `data/settings.json` | 默认字体、窗口尺寸、速度系数 |
| `data/variables.json` | 旧版兼容变量种子 |

### 8.2 系统设置

通过管理页面 → 系统设置 修改：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| UI 字体大小 | 10 | 全局字体缩放 |
| 主窗口尺寸 | 1280x800 | 宽x高 |
| 执行速度系数 | 1.0 | 延时统一缩放倍数 |
| 清零统计密码 | 0000 | 生产统计清零密码 |

### 8.3 计划设置（每个测试计划独立配置）

在管理页面 → 计划设置 中修改：

| 配置项 | 说明 |
|--------|------|
| 存储模式 | 本地 / 远程 |
| 本地日志/报告目录 | 默认 data/logs、data/reports |
| 远程存储报告和日志 | 开关 + 上传地址 |
| 逐用例 JSON 数据上报 | 开关 + 上报接口地址 |
| MES 服务器地址 | MES 交互地址 |
| 当前批次 | 批次号，随上报数据发送 |
| 工位 ID | 工位标识，上报数据携带 |

### 8.4 用户管理

| 默认账号 | 密码 | 角色 | 权限 |
|---------|------|------|------|
| admin | admin | 管理员 | 全部功能 |
| operator | operator | 操作员 | 仅执行页面 |

- 一键分权：用户管理页勾选"开启一键分权"，重启后显示登录页
- 统计清零密码：初始 `0000`，可在系统设置修改

## 10. 故障排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 启动报 `No module named 'PyQt5'` | PyQt5 未安装 | `pip install PyQt5` 或 `apt install python3-pyqt5` |
| 打包后双击无反应 | 检查 `_internal/` 是否完整 | 确认目录结构完整，重新拷贝 |
| ARM 设备上 x86 打包程序无法运行 | 架构不匹配 | 在 ARM 设备上用 `push_source_to_pi.sh ... onedir` 本机打包 |
| 脚本加载报错 `ModuleNotFoundError` | 扩展包缺失 | 将对应包放入 `data/ext_packages/`，重启软件 |
| 远程上报失败 | 网络或地址配置错误 | 检查计划设置中的 URL，检查网络连通性 |
| 开机自启不生效 | systemd 服务配置问题 | `journalctl -u eol-cit.service -n 50` 查看日志 |
| 图形界面不显示 | 无图形环境 | 安装 X11 或使用 Xvfb 虚拟显示 |
| 报告/日志越来越多 | 软件自动保留当天 | 正常行为，历史文件自动清理 |

## 11. 卸载与清理

### 11.1 源码运行卸载

```bash
# 删除源码目录
rm -rf Test_management_sw/
rm -rf venv/

# 删除数据（可选）
rm -rf ~/.config/EOL/
```

### 11.2 打包版卸载

```bash
# 删除打包目录
rm -rf /opt/eol/

# 删除 systemd 服务（如配置了开机自启）
sudo systemctl stop eol-cit.service
sudo systemctl disable eol-cit.service
sudo rm /etc/systemd/system/eol-cit.service
sudo systemctl daemon-reload
```

### 11.3 数据清理

运行数据在 `data/` 目录下，删除整个 `data/` 即可清理所有配置和数据。报告和日志会自动清理历史文件，无需手动处理。
