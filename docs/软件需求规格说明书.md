## 1. 引言

### 1.1 编写目的

本文档是「测试用例管理与执行软件」（以下简称"本软件"）的软件需求规格说明书（Software Requirements Specification，SRS），
用于固化为已定型版本的**需求基线**，作为后续开发、测试、验收、维护以及变更管理的依据。

本文档是对系统现有已实现并稳定运行功能的**需求固化**——软件已定型，本文档描述的是当前交付版本的实际行为，作为"应当如此"的规格基线。

### 1.2 项目背景

本软件是一套面向**产线/实验室测试工位**的测试方案管理与执行工具，解决以下业务痛点：

- 测试方案（计划/序列/用例）依赖手工脚本与纸质记录，难以统一管理。
- 需要一个可针对不同产品快速配置、修改并执行的**图形化测试执行平台**。
- 需要一个支持**人机交互**（SN 输入、过程确认弹窗、批量循环测量）的产线执行界面。
- 需要一个可持续**采集生产数据**（良率、良品/不良品、逐用例结果）并**上报服务器/MES** 的通道。

## 2. 运行环境与部署

### 2.1 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows（产线平板/工控机）、Linux（x86_64 / ARM64，如 RK3588、Jetson） |
| Python | 3.8+（开发环境 3.10） |
| 运行方式一（源码） | `python3 main.py` |
| 运行方式二（打包） | `python3 build_app.py` 或 `pyinstaller EOL.spec`，生成 `dist/EOL/` 独立程序，无需安装 Python |

### 2.2 部署产物结构

```
dist/EOL/
├── EOL(.exe)               # 主程序
├── _internal/              # 打包内置代码/UI/scripts/assets（只读，勿改动）
└── data/                   # 运行数据（可读写，升级不会被覆盖）
    ├── plans/              # 测试计划
    ├── logs/               # 运行日志与系统日志
    ├── reports/            # HTML 报告
    ├── pending_uploads/    # 逐用例上报失败暂存（待续传）
    ├── ext_packages/       # 【外部扩展包目录】测试脚本第三方依赖
    ├── stats.ini           # 生产统计（按日期分节累加）
    ├── users.json
    ├── settings.json
    └── variables.json
```

### 2.3 外部扩展包机制

- 每次加载测试脚本前，软件把 `data/ext_packages/` 与 `scripts/` 自动加入脚本的 `sys.path`。
- 产线电脑可往 `data/ext_packages/` 放入第三方库（paramiko、pyserial、numpy 等），**无需重新打包**。
- 打包内置依赖：PyQt5、PyYAML、requests、paramiko。
- 跨平台拷贝 C 扩展包（numpy、cryptography 等）须与目标平台一致。

## 3. 总体功能概述

### 3.1 核心业务页面

软件由三大核心页面/模块构成：

1. **登录**（可选，受"一键分权"控制）
2. **执行页面**（操作员核心页面）
3. **管理页面**（仅管理员），内嵌四个子页面：
   - 测试计划管理
   - 全局变量管理
   - 系统设置
   - 用户管理

### 3.2 权限分级

| 角色 | 执行页面 | 管理页面 | 计划/变量编辑 | 系统设置 | 统计清零 |
| --- | :---: | :---: | :---: | :---: | :---: |
| 管理员 | ✔ | ✔ | ✔ | ✔ | ✔（直接） |
| 操作员 | ✔ | ✘ | ✘ | ✘ | ✔（需密码） |

### 3.3 核心能力清单

- 多级测试计划管理：测试计划（PLAN）→ 测试序列 → 测试用例
- 五种用例类型：Action / Delay / Pop / Measurement / Loop
- 全局变量管理（int/str/float/list/dict）
- 生产统计看板（总数/良品/良率/不良率）
- 连续测试执行模式（逐轮计入统计与报告）
- 本地 / 远程多种报告与数据上报
- 产线触屏 Kiosk 全屏模式（底部状态栏电量/WiFi 显示）
- 内置脚本 API（test_api）

### 3.4 用例状态机

每条用例状态流转：

```
待执行 → 运行中 → PASS / FAIL / 跳过
```

## 4. 登录与权限管理

### 4.1 登录校验

- 输入用户名、密码，选择角色（管理员/操作员）。
- 角色必须与账号一致，否则拒绝登录。
- 启动强制登录由"一键分权"开关控制。

### 4.2 默认账号

| 用户名 | 密码 | 角色 | 权限 |
| --- | --- | --- | --- |
| admin | admin | 管理员 | 全部功能 |
| operator | operator | 操作员 | 仅执行页面 |

> 首次启动自动创建以上默认账号，可在【用户管理】中修改。

### 4.3 一键分权

- 在【用户管理】页设置"开启一键分权"。
- 开启：下次启动显示登录页，登录后才能使用。
- 关闭：下次启动直接以管理员身份进入管理页面。
- 默认不开启。

### 4.4 账户管理功能

- 新增 / 修改 / 删除账号。
- 修改密码（管理员可重置）。
- 账号字段：用户名、密码、角色、描述。

### 4.5 隐藏快捷键（管理员）

| 快捷键 | 功能 |
| --- | --- |
| Ctrl+M | 管理页面（仅管理员） |
| Ctrl+Shift+L | 重新登录 |
| Ctrl+Q | 退出 |

## 5. 执行页面需求（操作员核心页面）

### 5.1 页面布局

- 顶部标题栏：logo / 工位名称 / 时钟。
- 左侧：测试步骤树 + 执行日志。
- 右侧：产品信息 / 生产统计 / 总体状态 / 开始按钮。
- 底部：机器人状态栏（温度/电流/电压/电池%）。
- 底部状态栏：设备电量/电源与 WiFi 信号强度（Linux 下读取 /sys 与 /proc/net/wireless）。
- 产线触屏 Kiosk 模式：窗口始终全屏、无边框（系统顶栏与左侧坞自动隐藏），不再使用可配置窗口尺寸；F11 切换全屏/退出；全屏守护防止系统手势把窗口还原/最小化。

### 5.2 基本操作

1. **选择测试计划**：点击测试计划输入框弹出可选计划（`data/plans/`），点击加载；可"浏览其他位置"。
2. **开始执行**：点击右下角【▶ 开始】按钮开始运行。
3. **SN 由脚本输入**：页面不提供 SN 输入框，由脚本调用 `set_sn_to_Panel(sn)` 写入并实时显示；未写入显示 `--`。

### 5.3 控制操作

- 开始 / 暂停 / 恢复 / 停止。
- 运行中【▶ 开始】显示"▶ 执行中..."并置灰。
- 手动停止的运行**不计入**生产统计。
- 单轮结束自动恢复开始按钮，可执行下一台。

### 5.4 测试步骤树

- 两级结构：序列（可展开）→ 用例。
- 每行显示：编号 / 测试项名称 / 状态 / 耗时。
- 实时状态：待执行 → 运行中 → PASS / FAIL / 跳过。
- Loop 用例展开后逐组平铺显示每 session 的结果。

### 5.5 总体执行状态

- 右侧以大字醒目显示 PASS（绿）/ FAIL（红）。
- 状态持续显示直到下一轮测试开始才更新（便于操作员一眼辨识）。

### 5.6 产品信息与机器人状态

- 产品信息区：SN 码（只读）、测试计划、当前批次、测试节拍（最近一轮实测耗时秒）。
- 底部机器人状态栏：温度 / 电流 / 电压 / 电池%，由脚本 `set_robot_*` 实时刷新；未更新显示 `--`。

### 5.7 生产统计看板

| 指标 | 说明 |
| --- | --- |
| 总数量 | 当天累计测试产品数 |
| 良品数 / 不良品数 | 当天 PASS / FAIL 数量 |
| 良率 / 不良率 | 百分比 |
| 清零统计 | 需输入密码（初始 0000，可在系统设置修改），**只清空当天**数据 |

- 统计按日期分节累加存储于 `data/stats.ini`，页面只显示当天；不满零则历史数据保留。

### 5.8 日志面板

- 默认隐藏，点击【▼ 显示日志】展开实时日志（高度约为步骤区域 1/5）。
- 支持【清空日志】。
- 展开日志后步骤区域自动缩小。

### 5.9 连续测试执行模式

- 可在计划设置勾选「启动循环测试模式」，默认单次执行；启用需输入授权密码（仅限特殊耐久测试）。
- 连续模式下，一轮结束自动从头重新执行整个计划，直到手动停止或退出。
- 每轮结束计入当天生产统计（stats.ini）并生成该轮报告；仅保留最近一轮结果与报告。

### 6.3 用例通用配置项（所有类型共有）

| 配置项 | 说明 |
| --- | --- |
| 测试编号 | 可选字符串；报告与上报 caseId 的显示/回退标识 |
| 用例名称 | 字符串 |
| 执行类型 | Action / Delay / Pop / Measurement / Loop |
| 跳过此用例 | 勾选后执行时跳过，标记「跳过」，不参与统计、不影响总体结果 |

| 失败重试次数 | 非负整数 |
| 失败策略 | 失败后暂停执行 / 失败后继续下一条 |

### 6.4 五种用例类型详细定义

#### 6.4.1 Action（仅执行）

- 配置：脚本路径、目标函数名称（自动列出脚本函数）。
- 仅执行函数，不做结果判定；报告记录函数名与类型。

#### 6.4.2 Delay（延时）

- 配置：延时时长 + 单位（毫秒 / 秒 / 分钟）。
- 执行受全局"速度系数"统一缩放。

#### 6.4.3 Pop（人机交互弹窗）

- 配置：弹窗标题、显示内容（长度不限）、按钮1（返回 True）/按钮2（返回 False）文本。
- 结果可存入全局变量。
- 模态阻塞：是（等待操作员点击）/ 否（超时自动继续）。

#### 6.4.4 Measurement（测量）

- 配置：显示内容、脚本路径。
- 选择脚本后【加载函数】→ 选择函数 → 自动解析：
  - **输入参数表**：参数名 / 类型 / 值或绑定变量 / 来源（直接值 / 全局变量）
  - **返回值表**：返回项 / 类型 / 绑定变量 / 判定方式 / 阈值范围
- **判定方式**：等于 / 不等于 / 大于 / 小于 / 范围内（`lo~hi` 或 `lo,hi`）/ 包含 / 长度。
- **阈值留空**：只记录返回值，不做判定。
- **绑定变量可选**：执行完自动写入全局变量（不存在自动创建）；留空不影响判定。

##### 判定阈值写法

| 判定方式 | 阈值写法 | 含义 |
| --- | --- | --- |
| 等于 / 不等于 | `10`、`pass`、`[10,20,30]`、`{"a":1}` | 标量比较；list/dict 支持 JSON 结构比较 |
| 大于 / 小于 | `200`、`0.5` | 数值比较 |
| 范围内 | `100~300` / `100,300` / `100，300` | 下限 ≤ 返回值 ≤ 上限 |
| 包含 | list：元素值；dict：键名；字符串：子串 | 判断存在性 |
| 长度 | `3`、`>2`、`>=3`、`<5`、`2~4` | list/dict 元素个数比较 |

##### 返回值为 list / dict 时的处理

| 返回类型 | 返回项写法 | 效果 |
| --- | --- | --- |
| 标量 | `return` | 直接用该值判定 |
| list / dict | `return` 或 `*` | 取整个对象判定或绑定 |
| dict | 键名，如 `voltage` | 取 `ret["voltage"]` |
| dict 嵌套 | 点号路径 `nested.a.b` | 取深层值 |
| list | 下标 `0`/`1`/`2` | 取对应元素 |

#### 6.4.5 Loop（循环批量）

- 配置：YAML 数据路径、脚本路径、执行函数、解析函数（可选）、session 键名（默认 `sessions`）。
- session 键名以页面为准，找不到时回退 `sessions/items/data/tests/cases`，顶层是列表则直接使用。
- **YAML 两种格式**：
  - 扁平式：`{name, value, min_val, ...}` 整条即数据，函数自行判定。
  - 包装式：`{name, input: {...}, expected: {...}}`，expected 逐项判定。
- **函数调用自适应**：单字典参数函数传整条 dict；多形参函数按键名传参；无参函数直接调用。
- **判定三层**：页面覆盖配置优先 → expected 判定（`20~30` 自动按范围）→ 无 expected 时自动找返回值中 `pass/ok/result` 字段判定。
- 执行页平铺展示每组结果；HTML 报告完整输出全部 session 数据。

## 7. 全局变量管理需求

- 支持类型：int / str / float / list / dict（list/dict 用 JSON 文本填写）。
- 新增 / 编辑 / 删除 / 刷新。
- **全局变量随测试计划保存**：打开计划自动加载；编辑后保存计划写入文件；不同计划互不影响。
- 全局作用域，供该计划内所有用例（Measurement 参数、返回值绑定、Pop 结果、脚本）读写。
- 引用方式：直接写变量名，不加花括号。
  - Measurement 参数：来源选「变量」，值列填变量名。
  - 返回值绑定：绑定变量列填变量名。
  - 脚本内：`get_variable("name")` / `set_variable("name", value)`。

- 总数量、良品数、不良品数、良率、不良率——均按**当天**累加。

- 连续模式：一轮完成自动从头重新执行，直到手动停止/退出；每轮计入当天统计并生成该轮报告、仅保留最近一轮结果。

## 11. 报告与数据存储需求

### 11.1 报告生成（本地，始终生效）

- 每次运行生成 HTML 报告 + 运行日志。
- 默认目录：`data/reports/`、`data/logs/`（或计划设置自定义）。
- 文件名：`计划名_SN_时间戳.html` / `计划名_时间戳.log`。
- 报告内容：总体结果、通过/失败统计、每条用例状态与详情、Loop 全部分组数据。
- **本地保留按天配置**：默认只保留当天（1 天）；启动与每轮结束时按系统设置「报告保留天数」清理更早文件。

### 11.2 远程文件存储（可选）

- 计划设置勾选"启用远程存储报告和日志"并填地址后，每轮结束把 HTML 报告与日志以 `multipart/form-data` 上传。
- 字段：`report`（report.html）、`log`（日志）、`plan`、`sn`。
- 上传内容可选「仅报告 / 仅日志 / 两者」，上传策略可选「总是上传 / 仅失败时上传」。
- 上传成功/失败写入执行日志；失败不影响本地保存与测试流程。

### 11.3 逐用例 JSON 数据上报（可选，V1.4）

- 勾选「启用」并填上报接口地址后，每轮结束后把本轮全部用例结果以 `multipart/form-data` POST 一次到服务器（一轮一个 SN）。
- 表单字段：`det_data`（检测数据 JSON 对象，含全部用例 records[]）；`log_file`（日志文件，**仅失败 detResult=1 时**上传）。
- det_data 主要字段：lineId（系统设置产线ID）、stationId、productSn、batchId（当前批次，解析为 long）、detTime（yyyy-MM-dd HH:mm:ss）、deviceId（预留 0）、seriesId、detResult（0=全部通过 / 1=存在失败）、dtcCode（异常时故障码）、caseNum / passNum / failNum、records[]、isFinal、finalBom[]。
- records[] 元素：caseId、caseName、category、standard / actualInput（真实 JSON 对象）、result（0过/1败）、durationMs（毫秒）、testTime、deviceId、curveData（Loop 有 points 时）、extrinsic / intrinsic / parameters（Action 结构化结果）。
- 报文 `key` 字段：由脚本 `set_upload_key(key)` 回填，否则回退计划设置的上报密钥。
- 鉴权两种（可叠加）：① Token 认证（启用后启动执行时先 POST 登录接口获取 Token，请求头按 `Token字段名: 前缀+Token` 发送，默认 `Authorization: Bearer <token>`）；② HTTP Basic 认证（服务器用户名/密码均非空则附带）。
- **失败暂存与续传**：上报失败/异常时数据暂存 `data/pending_uploads/{计划}_{SN}_{时间戳}.json`；下次测试开始时自动续传，单条最多重试 3 次（间隔 1 秒），仍失败再次暂存；过期暂存按系统设置「待上报数据保留天数」（默认 2 天）清理。
- 详细字段定义与生成规则见《服务器对接接口文档.md》。

### 11.4 MES 远程模式

- 存储模式选"远程"且配置了 MES 服务器地址时，运行结束后额外 POST 汇总结果到 MES 接口。
- 接口地址 = 交互接口（若以 http 开头则直接使用），否则拼接为 `mes_server + '/' + 交互接口`。
- 报文 JSON：{plan, sn, station_id, overall, total, passed, failed, skipped, time, results}，可附带 HTTP Basic 认证。

## 12. 接口需求

### 12.1 上报接口分类

| 编号 | 数据类型 | 传输方式 | 场景 |
| --- | --- | --- | --- |
| 1 | 逐用例测试数据（JSON，V1.4） | HTTP POST，multipart/form-data（`det_data` 为 JSON 对象） | 每轮一次（一个 SN），records[] 含全部用例结果，入库用 |
| 2 | HTML 报告 | HTTP POST，multipart/form-data | 归档/人工查看 |
| 3 | 运行日志 | HTTP POST，multipart/form-data | 与报告一起归档 |
| 4 | MES 汇总（JSON） | HTTP POST，JSON body | 上报本轮整体结果 |

- 接口 1 与接口 4 报文均携带**工位 ID（station_id / stationId）**。
- 四个接口独立配置地址；任意失败仅记录日志/暂存续传，不影响本地流程。
- 判定成功：收到 HTTP 2xx 即成功（`resp.ok`）。

### 12.2 通用约定

- 编码 UTF-8；时间格式 `YYYY-MM-DD HH:MM:SS`（接口 1 的 detTime/testTime；用例耗时 durationMs 为毫秒级）。
- 密钥：逐用例 JSON 上报报文含密钥字段，由脚本 `set_upload_key` 回填（否则用计划设置的上报密钥）。
- 鉴权：接口 1 支持 Token 认证与 HTTP Basic 认证（配置见 6.2.1）；接口 2/3/4 可附 HTTP Basic 认证。

### 12.3 接口细节

完整字段表、阈值解析规则、报文示例见《服务器对接接口文档.md》第三章~第七章。

## 13. 非功能需求

### 13.1 性能与稳定性

- 支持 **7×24 小时**长时间不间断运行。
- 测试任务全部后台异步执行（QThread + Python 线程池），**主线程不阻塞**，界面持续响应。
- 暂停/启停实时响应（threading.Event + 短轮询 ≤50ms，延时切片 10ms 检查）。
- 全链路异常捕获：脚本执行、网络请求、文件读写、外部函数调用均 try-except，异常只记日志不崩溃。
- 崩溃防护：全局/线程/Qt 消息异常均接入系统日志；原生崩溃（SIGSEGV 等）经 faulthandler 落盘 `data/logs/crash_*.txt`；崩溃标记 `.prev_crash` 记录上次非正常退出，下次启动弹窗提示，绝不静默闪退。
- 内存泄漏防范：每次运行独立线程池并显式 shutdown；脚本按 mtime 缓存与失效。

### 13.2 并发与线程安全

- Qt 主线程仅负责渲染；工作线程严禁直接操作 UI，一律经信号槽/信号桥跨线程通信。
- 运行时上下文（RuntimeContext）用 RLock 保护，供 GUI 与工作线程并发读写。
- 日志桥（LogBridge）统一队列到 GUI 线程写 QTextEdit。

### 13.3 代码规范

- UI（.ui）文件与业务逻辑彻底分离，通过 QtUiLoader 加载；禁止业务逻辑写入 UI 定义。
- 内置 API 实现于 `context.build_api()`，须在返回字典注册。

### 13.4 可移植性

- 计划内脚本与 YAML 路径自动转为相对软件根目录的相对路径，打开时自动解析，可按文件名在 `scripts/` 下回退查找。
- 外部扩展包支持跨电脑迁移（平台需一致）。

### 13.5 可维护性

- 新增用例类型：登记 `paths.CASE_TYPES` → 引擎增加处理器 → 表单注册 → UI 同步。
- 新增内置 API：在 `context.build_api()` 添加即可。
