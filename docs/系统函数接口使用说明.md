# 系统函数接口使用说明（含引用关联图）

> 本文档对应软件框架 `app/` 目录下的全部系统函数，说明"能做什么、在哪个文件、被谁调用"。
> 当你遇到某个功能不正常时，按本文档的"引用关联"顺着链路定位到具体函数/文件即可修改。

---

## 1. 软件总架构与模块引用关系

```
main.py
  └─ app/main_flow.py  bootstrap()          启动入口
       └─ 创建共享对象并注入页面：
            SettingsManager(全局设置)  ┐
            VariableManager (全局变量) ├─ 传入 MainWindow
            UserManager     (用户)     │
            RuntimeContext  (运行时上下文/脚本API)
       └─ app/ui/main_window.py  MainWindow
            ├─ app/ui/execute_page.py   ExecutePage   （执行页面）
            ├─ app/ui/manage_page.py    ManagePage    （管理页面）
            │     └─ app/ui/settings_page.py  SettingsPage（系统设置）
            └─ app/core/engine.py       EngineWorker  （测试执行引擎）
```

**核心模块引用关系（谁 import 谁）：**

```
app/core/paths.py  ← 被几乎所有模块引用（路径/常量）
app/core/syslog.py ← 被绝大多数字节引用（日志）
app/core/api.py    ← 被 main_flow / script_loader / main_window 引用
app/core/context.py← 被 engine / main_flow / main_window / execute_page 引用
app/core/engine.py ← 引用 report / script_loader / context / variable_manager
app/core/report.py ← 引用于 engine（生成报告/上报）
app/core/script_loader.py ← 引用于 engine（加载/调用脚本函数）
app/core/plan_model.py ← 引用于 manage_page / execute_page / engine
app/core/settings_manager.py ← 引用于 main_flow / settings_page / main_window
app/core/user_manager.py ← 引用于 main_flow / login_dialog / users_page
```

## 3. `app/core/context.py` —— 运行时上下文（核心）

`RuntimeContext` 保存整个运行期间共享的数据，**线程安全**（内部用 RLock），
被 GUI 线程（执行页面）与引擎工作线程（EngineWorker）共同访问。

同时 `build_api()` 定义了**注入给用户测试脚本的全部内置函数**（通过 `test_api.*` 调用）。

### 3.1 运行时数据方法

| 方法 | 作用 | 被谁调用 |
|---|---|---|
| `set_sn(sn)` / `get_sn()` | 读写当前 SN | 引擎脚本 `set_sn_to_Panel`、执行页面 |
| `set_current_result/get_current_result/get_current_detail` | 当前用例结果 | 引擎 |
| `finish_case(result, detail)` | 用例收尾（记录 last 结果） | 引擎 |
| `get_last_result/get_last_detail` | 上次用例结果 | 引擎 |
| `set_overall/get_overall` | 总体结果 | 引擎、执行页面 |
| `set_display/get_display_info/reset_display` | 脚本显示信息 | 引擎（脚本 `set_display_info`） |
| `set_robot_status/get_robot_status` | 机器人状态温度/电流/电压/电池 | 引擎（脚本 `set_robot_*`）、执行页面 |
| `set_measure_result / set_measure_field / get_measure_*` | Loop 自描述测量结果 | 引擎（脚本测量 API） |
| `set_upload_key/get_upload_key` | 逐用例上报密钥 | 引擎（脚本 `set_upload_key`）、report |
| `set_station_info/get_station_id/get_station_name` | 工位 ID/名称（ID 上报后端，名称显示页面） | 执行页面、report |
| `emit_log(msg)` | 脚本日志回调 | 引擎 |

### 3.2 `build_api()` —— 注入给用户脚本的内置函数

这些函数以 `test_api.函数名(...)` 形式在用户测试脚本中直接可用：

| 函数 | 说明 |
|---|---|
| `set_sn_to_Panel(sn)` | 设置当前 SN 并显示到执行面板 |
| `get_sn()` | 读取当前 SN |
| `get_test_result()` | 当前用例结果 |
| `get_last_test_result()` / `get_last_test_detail()` | 上次结果/详情 |
| `get_display_info(key=None)` / `set_display_info(key, value)` | 显示信息 |
| `log(msg)` | 脚本日志（写入运行日志并显示） |
| `get_variable(name)` / `set_variable(name, value)` | 读写全局变量 |
| `set_robot_status(**kw)` `set_robot_temperature/current/voltage/battery` | 机器人状态 |
| `get_robot_status(key=None)` | 读取机器人状态 |
| `set_measure_result(...)` `set_measure_value/expected/range/message/field` `get_measure_*` `reset_measure_result()` | 测量结果 |
| `set_upload_key(key)` / `get_upload_key()` | 上报密钥 |
| `get_station_id()` / `get_station_name()` | 工位 ID/名称 |

> **要修改脚本可用 API**：到 `context.py` 的 `build_api()` 里添加函数，并同步在返回字典 `return {...}` 中注册。修改后脚本重启生效。

## 4. `app/core/engine.py` —— 测试执行引擎

`EngineWorker(QThread)` 在工作线程中按计划顺序执行用例，通过 Qt 信号把进度、
状态、日志回传给 GUI 线程（执行页面）。

### 4.1 对外控制方法（供执行页面调用）

| 方法 | 作用 | 被谁调用 |
|---|---|---|
| `run()` | 线程主入口，整体执行流程 | 线程启动 |
| `pause()/resume()/stop()` | 暂停/恢复/停止 | 执行页面按钮（若启用） |
| `_speed_ms(ms)` | 延时按速度系数缩放 | 引擎内部 |

### 4.2 信号（Engine → 界面）

| 信号 | 参数 | 界面处理函数 |
|---|---|---|
| `sig_log(str)` | 日志文本 | `execute_page.append_log` |
| `sig_case_state(id,state,detail,elapsed)` | 用例状态 | `execute_page._on_case_state` |
| `sig_case_sessions(id,list)` | Loop 会话结果 | `execute_page._on_case_sessions` |
| `sig_overall(str)` | 总体状态文本 | `execute_page._on_overall` |
| `sig_progress(done,total)` | 进度 | `execute_page._on_progress` |
| `sig_run_finished(ok,msg)` | 运行结束 | `execute_page._on_run_finished` |
| `sig_run_started()` | 开始 | `execute_page._on_run_started` |
| `sig_request_pop(dict)` | 请求人机交互弹窗 | `execute_page._on_pop_requested` |
| `sig_phase(str)` | 阶段 | `execute_page._on_phase` |

### 4.3 内部执行流水线（引用关联）

```
run()
 ├─ open_run_log()           → report.py
 ├─ _run_plan()              → 遍历 flatten_cases()（plan_model）
 │     └─ _execute_case()    派发到各类型处理
 │           ├─ _handle_action
 │           ├─ _handle_delay
 │           ├─ _handle_pop
 │           ├─ _handle_measurement
 │           └─ _handle_loop
 │                 └─ _load_sessions()（读YAML）→ script_loader
 ├─ 各 _handle_* 内部：
 │     ├─ load_function(script, func) → script_loader
 │     ├─ _safe_call(func, kwargs)     → 调用脚本（api 已注入）
 │     └─ _build_args/_convert/_extract/_judge_measurement/_judge_loop_session
 └─ _do_report(ok) → _do_report_impl()
       └─ report.py：
            save_local_report()      生成本地HTML报告
            send_remote_report()     MES远程上报
            upload_reports()         远程文件上传
            send_json_cases()        逐用例JSON上报
```

## 6. `app/core/script_loader.py` —— 脚本加载与调用

| 函数 | 作用 | 被谁调用 |
|---|---|---|
| `ensure_runtime_paths()` | 把 `data/ext_packages`、`scripts/` 加入 sys.path | 加载脚本时 |
| `load_script_module(script_path)` | 加载 .py 模块（缓存，按 mtime 失效），并注入 api | `list_functions`、`load_function` |
| `invalidate_script_cache()` | 清空模块缓存 | 调试器等 |

| `load_function(script_path, func_name)` | 返回可调用函数对象 | engine `_handle_*` |

## 7. `app/core/*.py` —— 数据与配置管理

### 7.1 `plan_model.py`（测试计划模型）
- `TestPlan`：`.to_dict/.from_dict/.save/.load/.flatten_cases/.total_cases`、`.settings`
- `TestSequence`：`.to_dict/.from_dict`
- `TestCase`：`.to_dict/.from_dict`，字段含 `type/timeout_ms/retry/fail_policy/skip/config`
- 被 `manage_page.py`（编辑）、`execute_page.py`（加载/执行）、`engine.py`（执行）引用。

### 7.2 `settings_manager.py`（全局设置）
- `SettingsManager`：`load()/save()/update(**kwargs)`
- 字段：`font_size/window_width/window_height/speed_factor/clear_password/station_id/station_name`
- 数据文件：`data/settings.json`
- 被 `main_flow`（创建）、`settings_page.py`（编辑）、`main_window.apply_settings`（应用）、`execute_page.refresh_station_title`（显示）引用。
- **要新增一个全局设置项**：先在 `__init__`/`load`/`save`/`update` 四处加字段，再到 `settings_page.py` 加输入框，最后在用到的地方读取。

### 7.3 `user_manager.py`（用户）
- `UserManager`：`verify/list_users/get/add/update/change_password/remove/set_require_login/get_require_login`
- 数据文件：`data/users.json`；被 `main_flow`、`login_dialog.py`、`users_page.py` 引用。

### 7.4 `variable_manager.py`（全局变量）
- `VariableManager`：`load/save/to_dict/load_dict/list_variables/get/exists/add/update/remove/get_value/set_value/cast`
- 数据文件：`data/variables.json`（旧版）+ 随 PLAN 保存。
- 被 `engine.build_args`、`main_flow`、`variables_page.py` 引用。

### 7.5 `syslog.py`（系统日志）
- `info/warn/error/exception(tag,exc)/log_exception_hook`
- 写入 `data/logs/system_*.log`。被整个框架引用。

### 7.6 `paths.py`（路径）
- 常量：`DATA_DIR/PLANS_DIR/LOGS_DIR/REPORTS_DIR/USERS_FILE/SETTINGS_FILE/VARIABLES_FILE/STATS_INI_FILE/UI_FILES/...`
- `relpath_from_root/resolve_root_path`：计划内路径的可移植解析。

## 10. 关键执行链路图示（文本版）

```
用户点"开始"（execute_page.start_run）
   └─ _build_engine() 创建 EngineWorker，连接信号

              ├─ upload_reports()       远程文件
              └─ send_json_cases()      逐用例JSON
信号 → execute_page._on_* → 刷新界面
```

## 11. 注意事项

1. **脚本 API** 的真正实现在 `context.build_api()`，`script_loader` 会在加载脚本时把 `test_api` 中注册的函数注入脚本命名空间；所以"加脚本函数"务必在 `build_api()` 的返回字典里注册。
2. **全局设置**需要"初始化默认值 + load 读取 + save 写入 + update 应用"四处一致，缺一会导致值丢失或读不到。
3. 修改**上报字段**后，后端接口也需要同步；字段在 `report.py` payload 处。
4. 新增字段建议遵循现有 `context.py` 的线程安全写法（统一加 `with self._lock`）。
