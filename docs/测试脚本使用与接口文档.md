## 1. 概述

本软件（EOL 测试管理系统）支持通过 Python 脚本定义测试逻辑。每个测试用例关联一个 `.py` 脚本中的函数，运行时由引擎动态加载并调用。

**核心流程：**

```
测试计划(.plan) → 测试序列(Sequence) → 测试用例(Case)
                                            ↓
                                    脚本文件 + 函数名
                                            ↓
                                    script_loader 动态加载
                                            ↓
                                    注入 test_api 内置函数
                                            ↓
                                    调用脚本函数，获取返回值
                                            ↓
                                    引擎根据用例类型判定结果(PASS/FAIL)
```

**关键路径：**

| 目录 | 说明 |
|------|------|
| `scripts/` | 用户测试脚本存放目录 |
| `scripts/*.yaml` | Loop 用例的批量测试数据 |
| `data/plans/` | 测试计划文件（`.plan`，JSON格式） |
| `tools/` | 开发调试工具（Mock 服务器、自动执行器等） |
| `app/core/engine.py` | 测试执行引擎 |
| `app/core/script_loader.py` | 脚本动态加载器 |
| `app/core/context.py` | 运行时上下文 + `build_api()`（内置 API 定义） |

## 2. 环境准备

### 2.1 安装依赖

```bash
pip install -r requirements.txt
```

依赖清单：

| 包名 | 最低版本 | 用途 |
|------|---------|------|
| PyQt5 | >=5.15 | GUI 框架（引擎依赖 QThread） |

| paramiko | >=3.0 | SSH/SFTP（远程部署用） |

### 2.2 启动软件

```bash
python3 main.py
```

默认账号：`admin` / `admin`（管理员），`operator` / `operator`（操作员）。

### 2.3 脚本目录约定

脚本文件必须放在 `scripts/` 目录下（或其子目录），引擎通过 `script_loader.py` 自动扫描该目录。脚本文件名即为软件界面中"脚本文件"下拉框的选项。

## 3. 脚本文件结构与规范

### 3.1 基本模板

```python
# -*- coding: utf-8 -*-
"""脚本说明：一句话描述本脚本的用途。"""
import test_api

def my_function(param1, param2="default"):
    """函数说明：会被软件界面的用例编辑器解析并展示。
    
    参数会显示在用例编辑界面，支持在界面或YAML中配置。
    
    Args:
        param1: 参数说明
        param2: 参数说明，默认值
    
    Returns:
        返回值会被引擎用于判定用例结果（见第5节）
    """
    # 你的测试逻辑
    test_api.log("正在执行: %s" % param1)
    
    result = do_something(param1, param2)
    return result
```

### 3.2 命名规则

- 脚本文件名：字母/数字/下划线，如 `demo_instrument.py`、`auto_api.py`
- 函数名：字母/数字/下划线，不能以数字开头
- **私有函数**（以 `_` 开头）不会出现在用例编辑器的函数选择列表中
- 脚本修改后，引擎会在下次调用时自动重新加载（按文件 mtime 判断）

### 3.3 函数签名解析

引擎会解析函数签名，自动在用例编辑界面生成参数输入框：

```python
# 无参数 → 界面无参数输入
def simple_action():
    return True

# 带默认值 → 界面显示参数名和默认值，可修改
def measure_voltage(channel=1, timeout=5):
    return {"value": 12.0}

# 类型注解 → 引擎辅助类型转换
def add(a: int, b: int) -> int:
    return a + b
```

### 3.4 函数返回值约定

| 用例类型 | 返回值要求 | 判定规则 |
|---------|-----------|---------|
| **Action** | 任意（`True`=通过，其他=失败） | `True` → PASS，其他 → FAIL |
| **Delay** | 无需返回（仅等待） | 自动 PASS |
| **Pop** | 无需返回（弹窗交互） | 用户确认 → PASS，取消 → FAIL |
| **Measurement** | `dict` 或标量值 | 见 5.4 节 |
| **Loop** | `dict`（含 `pass` 字段）或标量值 | 见 5.5 节 |

## 4. 内置 API 完整参考

所有内置 API 通过 `test_api` 模块调用。脚本文件顶部 `import test_api` 后即可使用。

### 4.1 SN 管理

```python
test_api.set_sn_to_Panel(sn: str) -> bool
```
设置当前 SN 号并显示到执行面板。通常在扫码用例或自动测试开头调用。

```python
test_api.get_sn() -> str
```
读取当前 SN 号。

### 4.2 日志输出

```python
test_api.log(msg: str) -> bool
```
写入执行日志并实时显示在日志面板。线程安全，可在任意线程调用。

```python
# 示例
test_api.log("开始测量电压")
test_api.log("测量结果: %.3f V" % voltage)
test_api.log("SN=%s 测试完成" % test_api.get_sn())
```

### 4.3 全局变量

```python
test_api.get_variable(name: str) -> any
test_api.set_variable(name: str, value: any) -> bool
```
读写全局变量（跨用例共享数据）。

```python
# 示例：用例A写入，用例B读取
test_api.set_variable("calib_done", True)
result = test_api.get_variable("calib_done")
```

### 4.4 显示信息

```python
test_api.set_display_info(key: str, value: any) -> bool
test_api.get_display_info(key: str = None) -> any
```
在执行页面的"显示信息"区域设置/读取键值对。

```python
test_api.set_display_info("功耗", "18.5W")
test_api.set_display_info("状态", "正常")
```

### 4.5 机器人状态

```python
test_api.set_robot_temperature(value) -> bool
test_api.set_robot_current(value) -> bool
test_api.set_robot_voltage(value) -> bool
test_api.set_robot_battery(value) -> bool
test_api.set_robot_status(**kwargs) -> bool      # 批量设置
test_api.get_robot_status(key=None) -> dict/any  # 读取
```

更新执行页面底部的机器人状态栏（温度/电流/电压/电池）。

```python
test_api.set_robot_temperature(25.5)
test_api.set_robot_current(1.2)
test_api.set_robot_voltage(12.3)
test_api.set_robot_battery(87)
# 或批量设置
test_api.set_robot_status(temperature=25.5, current=1.2, voltage=12.3, battery=87)
```

### 4.6 测量结果（Measurement / Loop 通用）

```python
# 完整设置（推荐在 Loop 自描述模式使用）
test_api.set_measure_result(
    value=12.0,           # 实际值
    expected="11~13",     # 期望值/范围描述
    unit="V",             # 单位
    lower=11.0,           # 下限
    upper=13.0,           # 上限
    passed=True,          # 判定结果
    message="电压正常"     # 消息
)

# 分步设置
test_api.set_measure_value(12.0, unit="V")
test_api.set_measure_expected("11~13")
test_api.set_measure_range(11.0, 13.0)
test_api.set_measure_message("电压正常")
test_api.set_measure_field("custom_key", "custom_value")  # 自定义字段

# 读取
value = test_api.get_measure_value()
expected = test_api.get_measure_expected()
lower, upper = test_api.get_measure_range()
message = test_api.get_measure_message()
result = test_api.get_measure_result()  # 返回全部字段的 dict

# 重置
test_api.reset_measure_result()
```

### 4.7 上报密钥

```python
test_api.set_upload_key(key: str) -> bool
test_api.get_upload_key() -> str
```
设置/读取逐用例 JSON 上报的密钥。密钥通常从服务器获取。

```python
# 从服务器获取密钥后回填
ok, resp = requests.get("http://server/api/key?sn=%s" % sn)
if ok:
    test_api.set_upload_key(resp["data"]["key"])
```

### 4.8 工位信息

```python
test_api.get_station_id() -> str    # 工位ID（上报用）
test_api.get_station_name() -> str  # 工位名称（显示用）
```

### 4.9 用例结果查询

```python
test_api.get_test_result() -> bool/None       # 当前用例结果
test_api.get_last_test_result() -> bool/None  # 上一个用例结果
test_api.get_last_test_detail() -> str        # 上一个用例详情
```

## 5. 五种用例类型及脚本写法

### 5.1 Action（动作用例）

**用途：** 执行操作，不做自动判定。如上电、发送指令、保存数据。

**脚本写法：**

```python
def power_on(voltage=12.0):
    """上电操作"""
    test_api.log("上电: %.1fV" % voltage)
    # ... 硬件操作 ...
    return True  # True=执行成功
```

**判定规则：**
- 返回 `True` → PASS
- 返回其他值（`False`/`None`/异常）→ FAIL

### 5.2 Delay（延时用例）

**用途：** 等待指定时间。无需脚本函数，纯配置。

**配置字段：**
- `delay_ms`：等待毫秒数

### 5.3 Pop（人机交互用例）

**用途：** 弹窗等待人工确认。无需脚本函数，纯配置。

**配置字段：**
- `title`：弹窗标题
- `description`：弹窗内容
- 点击"确认" → PASS，点击"取消" → FAIL

### 5.4 Measurement（测量用例）

**用途：** 测量一个值并与阈值比较。支持多种判定模式。

**脚本写法（返回标量）：**

```python
def measure_voltage(channel=1):
    """测量电压，返回数值"""
    import random
    value = 12.0 + random.uniform(-0.1, 0.1)
    return round(value, 3)  # 返回数值，引擎按阈值判定
```

**脚本写法（返回字典）：**

```python
def measure_voltage(channel=1):
    """测量电压，返回字典"""
    value = 12.0
    return {"voltage": value, "unit": "V", "channel": channel}
```

**判定模式（在用例编辑界面配置）：**

| 模式 | 说明 | 配置 |
|------|------|------|
| **返回项判定** | 从返回值提取指定字段比较 | "返回项"列填写字段名，如 `voltage` |
| **固定值等于** | 实际值 == 阈值 | 阈值填 `12` |
| **范围内** | 下限 <= 实际值 <= 上限 | 阈值填 `11,13` 或 `11~13` |
| **大于** | 实际值 > 阈值 | 阈值填 `>200` |
| **小于** | 实际值 < 阈值 | 阈值填 `<0.5` |
| **自描述** | 脚本自行判定（推荐） | "自描述"列勾选，脚本调用 `set_measure_result` |

**自描述模式示例（推荐）：**

```python
def measure_custom(params: dict) -> dict:
    """自描述测量：脚本自行判定，结果写入报告"""
    value = 12.3
    expected = 12.0
    lower, upper = 11.0, 13.0
    passed = lower <= value <= upper
    
    # 写入测量结果（会出现在报告和上报数据中）
    test_api.set_measure_result(
        value=value, expected=expected, unit="V",
        lower=lower, upper=upper, passed=passed,
        message="电压 %.3fV 在 [%.1f, %.1f] 范围内" % (value, lower, upper)
    )
    return {"value": value, "pass": passed}
```

### 5.5 Loop（循环用例）

**用途：** 从 YAML 文件批量读取测试数据，逐条调用脚本函数。

**脚本写法（统一入口，params 为 YAML 中的一条 session）：**

```python
def loop_test_entry(params):
    """Loop 统一入口：每个 session 调用一次。
    
    Args:
        params: YAML 中一个 session 的全部字段（dict）
                包含 name, expected, lower, upper, timeout 等
    
    Returns:
        dict: 必须包含 "pass" 字段（True/False），
              其余字段会作为测量数据上报
    """
    item_name = params.get("name", "unknown")
    url = params.get("path", "")
    
    # 你的测试逻辑
    ok, resp = do_request(url)
    
    # 判定
    passed = ok and resp.get("code") == 0
    
    return {
        "value": resp.get("data"),
        "pass": passed,
        "message": "%s: %s" % (item_name, "OK" if passed else "FAIL")
    }
```

**YAML 数据文件格式见 [第6节](#6-loop-数据-yaml-配置)。**

## 6. Loop 数据 YAML 配置

### 6.1 文件格式

```yaml
# 文件名：demo_loop.yaml
sessions:
  - name: "测试项名称1"         # 必填：显示在报告中
    # 以下字段按需添加，脚本通过 params.get() 读取
    param1: value1
    param2: value2
    expected: expected_value     # 期望值（可选）
    lower: 10                    # 下限（可选）
    upper: 20                    # 上限（可选）
    timeout: 5                   # 超时秒数（可选，默认5）

  - name: "测试项名称2"
    param1: value3
    ...
```

### 6.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 测试项名称，显示在报告和日志中 |
| `expected` | any | 否 | 期望值，可用于 `==` 判定或范围描述 |
| `lower` | number | 否 | 阈值下限 |
| `upper` | number | 否 | 阈值上限 |
| `timeout` | number | 否 | 请求超时（秒），默认 5 |
| 其他 | any | 否 | 自定义字段，脚本通过 `params.get()` 读取 |

### 6.3 常用模式示例

**命令接口测试：**

```yaml
sessions:
  - name: "list指令"
    cmd: "list"
    timeout: 3
    expected: {"code": 0, "msg": "ok"}

  - name: "describe指令"
    cmd: "describe"
    id: "ver.bsp"
    timeout: 3
    expected: {"code": 0, "msg": "ok"}
```

**数值范围测试：**

```yaml
sessions:
  - name: "电压_正常"
    path: "/api/voltage"
    expected: 12
    lower: 11
    upper: 13
    timeout: 3

  - name: "电压_超上限(应FAIL)"
    path: "/api/voltage"
    expected: 12
    lower: 11
    upper: 11.1   # 故意设窄，触发 FAIL
    timeout: 3
```

**边界/异常测试：**

```yaml
sessions:
  - name: "404错误"
    path: "/api/missing"
    timeout: 3

  - name: "500错误"
    path: "/api/error"
    timeout: 3

  - name: "慢响应"
    path: "/api/slow?t=3"
    timeout: 5

  - name: "超时"
    path: "/api/timeout"
    timeout: 2   # 服务端延迟10秒，客户端2秒超时
```

## 7. Mock 服务器搭建与使用

Mock 服务器用于本地离线测试，模拟产线真实服务。

### 7.1 启动 Mock 服务器

```bash
# Auto 模式（默认，端口 5000）—— 模拟产线测试服务
python3 tools/mock_server.py --port 5000 --mode auto

# CIT 模式（端口 8090）—— 模拟 CIT 协议服务
python3 tools/mock_server.py --port 8090 --mode cit

# 同时运行两套（后台）
python3 tools/mock_server.py --port 5000 --mode auto &
python3 tools/mock_server.py --port 8090 --mode cit &
```

### 7.2 Auto 模式接口列表

| 方法 | 路径 | 说明 | 返回值 |
|------|------|------|--------|
| GET | `/status` | 服务状态 | `{"code":0, "msg":"ok", "data":{"status":"running"}}` |
| GET | `/api/key?sn=XXX` | 获取上报密钥 | `{"code":0, "msg":"ok", "data":{"key":"SECRET-KEY-XXX"}}` |
| GET | `/api/robot/status` | 机器人状态 | `{"code":0, "msg":"ok", "data":{"temperature":25.5, "current":1.2, "voltage":12.3, "battery":87}}` |
| GET | `/api/voltage` | 电压读数 | `{"code":0, "msg":"ok", "data":{"value":12.0, "unit":"V"}}` |
| GET | `/api/current` | 电流读数 | `{"code":0, "msg":"ok", "data":{"value":0.8, "unit":"A"}}` |
| GET | `/api/temperature` | 温度读数 | `{"code":0, "msg":"ok", "data":{"value":25.0, "unit":"℃"}}` |
| GET | `/api/battery` | 电池电量 | `{"code":0, "msg":"ok", "data":{"value":87}}` |
| GET | `/api/sum?a=&b=` | 求和 | `{"code":0, "msg":"ok", "data":{"sum":3.0}}` |
| GET | `/api/list` | 列表数据 | `{"code":0, "msg":"ok", "data":[0,42,20,30,5]}` |
| GET | `/api/dict` | 字典数据 | `{"code":0, "msg":"ok", "data":{"nested":{"a":1,"b":"x"}}}` |
| GET | `/api/str` | 字符串 | `{"code":0, "msg":"ok", "data":"running"}` |
| GET | `/api/bool` | 布尔值 | `{"code":0, "msg":"ok", "data":true}` |
| GET | `/api/range?lo=&hi=` | 范围中值 | `{"code":0, "msg":"ok", "data":{"value":50.0}}` |
| GET | `/api/slow?t=` | 慢响应 | 延迟 t 秒后返回 |
| GET | `/api/timeout` | 永不返回 | 延迟 10 秒（客户端超时测试） |
| GET | `/api/error` | 500 错误 | HTTP 500 |
| GET | `/api/missing` | 404 | HTTP 404 |
| POST | `/api/request` | 指令转发 | `{"code":0, "msg":"ok", "data":{"echo":"cmd"}}` |
| POST | `/submit` | 数据上报 | 记录到日志文件 |

### 7.3 CIT 模式接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/sysinfo` | 系统信息（CPU/内存/OS等） |
| POST | `/api/request` | CIT 协议：`cmd=list|describe|run` |
| POST | `/submit` | 数据上报 |

### 7.4 脚本中调用 Mock 服务

```python
import requests
import test_api

MOCK_BASE = "http://localhost:5000"  # 或 http://10.5.35.49:5000

def measure_voltage(params=None):
    """调用 Mock 电压接口"""
    try:
        r = requests.get(f"{MOCK_BASE}/api/voltage", timeout=5)
        r.raise_for_status()
        data = r.json()
        value = data["data"]["value"]
        return {"value": value, "pass": True}
    except Exception as e:
        test_api.log("请求失败: %s" % e)
        return {"value": 0, "pass": False}
```

### 7.5 上报数据验证

Mock 服务器的 `/submit` 端点会将收到的上报数据追加到日志文件：

```bash
# 默认日志路径
data/logs/mock_submissions.log

# 自定义日志路径
python3 tools/mock_server.py --port 5000 --mode auto --submit-log /tmp/submit.log
```

用 `tools/analyze_submitted.py` 分析上报日志：

```bash
python3 tools/analyze_submitted.py data/logs/mock_submissions.log
```

## 8. 无界面自动执行

### 8.1 单次执行

```bash
python3 tools/auto_run_plan.py <计划文件路径> [--sn SN号] [--pop yes|no] [--timeout 600]
```

参数说明：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `plan` | （必填） | `.plan` 文件路径 |
| `--sn` | `AUTOTEST-SN-001` | 被测产品 SN |
| `--pop` | `yes` | Pop 弹窗自动确认(`yes`)或自动取消(`no`) |
| `--timeout` | `600` | 整体执行超时（秒） |

示例：

## 10. 脚本调试技巧

### 10.1 在管理页面调试运行

2. 选择脚本文件和函数
3. 填写参数
4. 点击"调试运行"

### 10.2 日志输出

```python
test_api.log("变量值: %s" % my_var)
test_api.log("请求结果: %s" % resp.json())
```

### 10.3 常用调试模式

```python
# 模式1：直接运行脚本（独立于软件）
if __name__ == "__main__":
```

## 11. 常见问题与排查

### Q1: 脚本函数不出现在用例编辑器的下拉列表中

**检查：**
- 函数名是否以 `_` 开头（私有函数会被过滤）
- 脚本文件是否在 `scripts/` 目录下
- 脚本是否有语法错误（查看日志）

### Q2: 脚本中 `import test_api` 报错

**解决：** 确保在软件环境中运行（通过引擎加载）。独立运行脚本时需要模拟 `test_api`（见 10.3 节）。

### Q3: Loop 用例执行后无结果

**检查：**
- YAML 文件格式是否正确（注意缩进）
- YAML 中 `sessions` 列表是否为空
- 脚本函数是否接受 `params` 参数

### Q4: 测量值判定与预期不符

**检查：**
- 阈值格式：`11,13` 或 `11~13` 表示范围，`12` 表示固定值
- 自描述模式是否正确调用了 `set_measure_result`
- `pass` 字段是否正确设置

### Q5: JSON 上报失败

**检查：**
- 计划设置中的上报 URL 是否正确
- 服务器是否返回 HTTP 2xx
- `set_upload_key()` 是否在上报前调用
- 失败数据会保存到 `data/pending_uploads/`，下次运行时自动重试

### 示例1：HTTP 接口测试脚本

```python
# -*- coding: utf-8 -*-
"""API 接口测试脚本：演示 GET/POST 请求与 JSON 判定"""
import requests
import test_api

SERVER = "http://10.5.35.49:5000"


def ping(params=None):
    """动作：检查服务是否存活"""
    try:
        r = requests.get(f"{SERVER}/status", timeout=5)
        ok = r.status_code == 200
        test_api.log("ping: %s" % ("OK" if ok else "FAIL"))
        return ok
    except Exception as e:
        test_api.log("ping 失败: %s" % e)
        return False


def measure_voltage(params=None):
    """测量：获取电压值"""
    try:
        r = requests.get(f"{SERVER}/api/voltage", timeout=5)
        data = r.json()
        value = data["data"]["value"]
        test_api.log("电压: %.3f V" % value)
        return value  # 返回标量，引擎按阈值判定
    except Exception as e:
        test_api.log("测量失败: %s" % e)
        return 0


def loop_api_test(params):
    """Loop：逐条测试 API 接口"""
    name = params.get("name", "unknown")
    path = params.get("path", "/api/status")
    expected_code = params.get("expected_code", 0)
    timeout = params.get("timeout", 5)

    try:
        r = requests.get(f"{SERVER}{path}", timeout=timeout)
        resp = r.json()
        code = resp.get("code", -1)
        passed = code == expected_code

        test_api.set_measure_value(code, unit="code")
        test_api.set_measure_expected(expected_code)
        test_api.set_measure_message(
            "%s: code=%s expected=%s" % (name, code, expected_code)
        )
        return {"value": code, "pass": passed, "code": code}
    except Exception as e:
        test_api.log("%s FAIL: %s" % (name, e))
        return {"value": None, "pass": False, "message": str(e)}
```

### 示例2：带 HTTP 请求封装的通用脚本

```python
# -*- coding: utf-8 -*-
"""通用接口测试封装"""
import requests
import test_api


def request_api(url, method="GET", params=None, headers=None, timeout=10):
    """封装 requests，返回 (success, data_or_error)"""
    try:
        if method.upper() == "POST":
            resp = requests.post(url, json=params, headers=headers, timeout=timeout)
        else:
            resp = requests.get(url, params=params, headers=headers, timeout=timeout)
        resp.raise_for_status()
        return True, resp.json() if resp.content else {}
    except Exception as e:
        return False, "%s: %s" % (type(e).__name__, e)


def compare_thresholds(item_name, value, lower=None, upper=None, expected=None):
    """阈值对比，返回 (passed, message)"""
    if upper is not None and value is not None and float(value) > float(upper):
        return False, "%s: 超上限, 实际=%s, 上限=%s" % (item_name, value, upper)
    if lower is not None and value is not None and float(value) < float(lower):
        return False, "%s: 低于下限, 实际=%s, 下限=%s" % (item_name, value, lower)
    if expected is not None and value != expected:
        return False, "%s: 不匹配, 实际=%s, 期望=%s" % (item_name, value, expected)
    return True, "%s: 通过, 值=%s, 范围=[%s, %s]" % (item_name, value, lower, upper)


def api_test(params):
    """Loop 入口：GET 接口 + 阈值判定"""
    name = params.get("name", "test")
    url = params.get("url", "")
    method = params.get("method", "GET").upper()
    body = params.get("body")
    expected = params.get("expected")
    lower = params.get("lower")
    upper = params.get("upper")
    timeout = params.get("timeout", 5)

    ok, resp = request_api(url, method=method, params=body, timeout=timeout)
    if not ok:
        return {"value": None, "pass": False, "message": "请求失败: %s" % resp}

    # 提取值
    data = resp.get("data", resp)
    value = data.get("value", data) if isinstance(data, dict) else data

    # 判定
    passed, msg = compare_thresholds(name, value, lower, upper, expected)
    test_api.set_measure_value(value)
    if expected is not None:
        test_api.set_measure_expected(expected)
    if lower is not None and upper is not None:
        test_api.set_measure_range(lower, upper)
    test_api.set_measure_message(msg)
    test_api.log(msg)

    return {"value": value, "pass": passed, "message": msg}
```
