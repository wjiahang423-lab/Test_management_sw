# 测试用例管理与执行软件 —— 服务器对接接口文档

版本：1.1
日期：2026-08-20
适用对象：服务器端开发人员（接收产线软件上报的数据）

---

## 1. 概述

产线端「测试用例管理与执行软件」（EOL）每轮测试结束后向服务器上报四类数据：

| 编号 | 数据类型 | 传输方式 | 场景 |
| --- | --- | --- | --- |
| 1 | 逐用例测试数据（JSON） | HTTP POST，JSON body | 每个测试用例一条记录（含 SN/批次/**工位ID**/实际值/阈值），入库用 |
| 2 | HTML 测试报告 | HTTP POST，`multipart/form-data` | 归档/人工查看用 |
| 3 | 运行日志（log） | HTTP POST，`multipart/form-data` | 与报告一起归档 |
| 4 | MES 结果汇总（JSON） | HTTP POST，JSON body | 向 MES 上报本轮整体结果（含工位ID） |

其中接口 1（JSON 上报）与接口 4（MES 上报）的报文中均携带**工位 ID（station_id）**，
工位 ID 在产线软件的【系统设置 → 全局基础设置】中配置，标识数据来自哪个工位。

四个接口**相互独立**，在产线软件的【计划设置】里分别配置地址；任意一个失败都不影响产线本地测试流程，仅记录到执行日志。

> 产线软件侧的判定规则：只要能收到 **HTTP 2xx** 响应即视为"上报成功"（`requests` 的 `resp.ok`）。
> 因此请务必对成功请求返回 2xx 状态码；建议同时返回 JSON 并附业务状态码（见各接口示例）。

---

## 2. 通用约定

- 字符编码：`UTF-8`。
- 时间格式：`YYYY-MM-DD HH:MM:SS`（本地产线时间），如 `2026-08-17 14:00:00`。
- 所有字段值可能包含中文，服务器按 UTF-8 解析。
- 三个接口的 URL 均由产线端在计划设置中填写，服务器保证对应路径可访问即可。
- 密钥：逐用例 JSON 上报要求密钥（一个 SN 一组密钥）。产线端由**测试脚本**从产品/服务器获取后通过
  `set_upload_key(key)` 回填，上报报文的 `key` 字段即该值；服务器据此校验归属。

## 3. 接口一：逐用例 JSON 数据上报（数据入库）

### 3.1 请求

- **方法**：`POST`
- **URL**：产线【计划设置 → 逐用例 JSON 数据上报 → 上报接口地址】
- **Content-Type**：`application/json`（`requests` 自动设置）
- **频率**：每轮测试结束后上报一次（同一轮内所有用例在一次请求中一次性提交）

### 3.2 请求体

```json
{
  "key": "SECRET-KEY-001",
  "sn": "SN-20260817-001",
  "batch": "B-20260817",
  "station_id": "01",
  "test_time": "2026-08-18 16:11:27.123",
  "records": [
    {
      "test_time": "2026-08-18 16:11:27.123",
      "batch": "B-20260817",
      "sn": "SN-20260817-001",
      "case_name": "电压测量",
      "type": "measurement",
      "status": "PASS",
      "value": 12.2,
      "expected": "11~13",
      "threshold_upper": 13.0,
      "threshold_lower": 11.0
    },
    {
      "test_time": "2026-08-18 16:11:27.123",
      "batch": "B-20260817",
      "sn": "SN-20260817-001",
      "case_name": "CAN循环",
      "type": "loop",
      "status": "FAIL",
      "value": null,
      "expected": null,
      "threshold_upper": null,
      "threshold_lower": null,
      "list": [
        {
          "name": "信号点1",
          "status": "PASS",
          "value": "pass",
          "expected": "result=pass",
          "threshold_upper": null,
          "threshold_lower": null,
          "message": "result 等于 pass = True"
        }
      ]
    }
   ...
  ]
}
```

> `test_time` 已升级为毫秒级：`YYYY-MM-DD HH:MM:SS.mmm`。

### 3.3 字段说明

**顶层字段：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| key | string | 是 | 上报密钥（每组数据一个密钥），用于服务器校验/归属 |
| sn | string | 是 | SN 号（本轮被测产品） |
| batch | string | 是* | 批次号（计划设置中的"当前批次"，可为空字符串） |
| station_id | string | 是* | **工位 ID**（产线系统设置中配置，标识数据来自哪个工位，可为空字符串） |
| test_time | string | 是 | 上报时间（毫秒级，格式 `YYYY-MM-DD HH:MM:SS.mmm`） |
| records | array | 是 | 用例结果记录数组，**每个测试用例一条** |

**records 元素：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| test_time | string | 是 | 测试时间，同顶层 `test_time` |
| batch | string | 是* | 批次号，同顶层 `batch` |
| sn | string | 是 | SN 号，同顶层 `sn` |
| case_name | string | 是 | 测试用例名称（Loop 为用例名，不含 session 名） |
| type | string | 是 | 用例类型：`action` / `delay` / `pop` / `measurement` / `loop` |
| status | string | 是 | 判定状态：`PASS` / `FAIL` / `跳过` |
| value | any | 是 | 实际测量值（int/float/string/bool/list/object 都可能，按返回类型原样给出；Loop 父节点为 null） |
| expected | any/null | 是* | 期望值（YAML/计划配置的 `expected`，字典转 `code=0, msg=ok` 字符串；Measurement 为判定阈值，Action/Delay/Pop 等为 null） |
| threshold_upper | number/null | 是* | 阈值上限（解析规则见 3.4） |
| threshold_lower | number/null | 是* | 阈值下限（解析规则见 3.4） |
| list | array/null | 否 | **仅 Loop 类型存在**：子项列表，每个子项含 `name/status/value/expected/threshold_upper/threshold_lower/message` |

**Loop 子项（list 元素）字段：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name | string | YAML 里的 session 名称（用例名） |
| status | string | 该子项判定：`PASS` / `FAIL` |
| value | any | 该子项实际测量值 |
| expected | any/null | 该子项期望值（字符串或范围） |
| threshold_upper / threshold_lower | number/null | 该子项阈值上下限 |
| message | string | 判定详情/失败原因 |

> \* `batch`、`station_id`、`expected`、`threshold_upper`、`threshold_lower` 语义上允许空值，但字段本身始终存在（值为 `""` / `null`）。

### 3.4 阈值上下限取值规则（固定值）

| 阈值写法 | threshold_lower | threshold_upper | 备注 |
| --- | --- | --- | --- |
| 单值固定值 `5` / `100` | 5 / 100 | 5 / 100 | 等于判定 |
| 范围 `11~13` 或 `11,13` | 11 | 13 | 范围内判定 |
| 大于 `200` | 200 | null | 大于判定 |
| 小于 `0.5` | null | 0.5 | 小于判定 |
| 非数值 `pass` / `fail` / `OK` | null | null | 无法数值化，实际值按文本上报 |

**各用例类型的 records 生成规则：**

| 用例类型 | records 条数 | 说明 |
| --- | --- | --- |
| Measurement | 每个"返回项"一条 | 返回项=「返回项」列配置（默认 `return`）；value=该项实际值，上下限按 3.4 解析 |
| Loop | 父节点一条 + `list` 子项 | 父节点 `type=loop`、`status`=用例整体；`list` 内每个 session 一条，含 name/status/value/expected/上下限/message |
| Action / Delay / Pop | 一条 | value=结果状态字符串（PASS / FAIL / 跳过）；上下限为 null |

### 3.5 响应

成功：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"code": 0, "message": "ok"}
```

建议：服务器收到并成功入库后返回 2xx；校验失败（如密钥错误、字段缺省）返回 4xx，并发可选地携带错误信息。产线端仅依据状态码判断成功与否并写入执行日志。

## 4. 接口二：HTML 报告上传

### 4.1 请求

- **方法**：`POST`
- **URL**：产线【计划设置 → 远程文件存储 → 上传服务器地址】
- **Content-Type**：`multipart/form-data`

### 4.2 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| report | file | HTML 测试报告文件（表单文件名 `report.html`，MIME `text/html`） |
| log | file | 运行日志文本文件（表单文件名 `<日志文件名>.log`，MIME `text/plain`） |
| plan | string | 测试计划名称 |
| sn | string | SN 号 |

> `report` 与 `log` 至少其一存在（二者同时生成，正常都会上传）。若服务器仅需报告，忽略 `log` 字段即可。

### 4.3 请求示例（curl）

```bash
curl -X POST http://192.168.1.100:8000/upload \
  -F "report=@示例测试计划_SN123_20260817_140000.html" \
  -F "log=@示例测试计划_20260817_140000.log" \
  -F "plan=示例测试计划" \
  -F "sn=SN123"
```

### 4.4 响应

成功返回 2xx 即可（如 `200 OK`）。可返回 JSON：`{"code": 0, "message": "ok"}`。

---

## 5. 接口三：运行日志上传

日志随报告一起以 `multipart/form-data` 上传（见接口二字段表 `log` 字段），**没有单独接口**。
产线端启用「远程存储报告和日志」后，报告与日志每次同时上传到同一个地址。

> 若需要把日志单独存储/单独接口，请与产线端确认；当前版本日志与报告统一按接口二处理。

## 6. 接口四：MES 结果上报（综合汇总）

### 6.1 请求

- **方法**：`POST`
- **URL**：由计划设置的 `mes_server` 与 `mes_interface` 组合而成：
  - 若 `mes_interface` 以 `http://`/`https://` 开头，则直接使用 `mes_interface`；
  - 否则为 `mes_server.rstrip("/") + "/" + mes_interface.lstrip("/")`。
- **Content-Type**：`application/json`
- **频率**：每轮测试结束后上报一次（汇总本轮整体结果）

### 6.2 请求体

```json
{
  "plan": "机器人下线测试",
  "sn": "SN-20260817-001",
  "station_id": "01",
  "overall": true,
  "total": 10,
  "passed": 9,
  "failed": 1,
  "skipped": 0,
  "time": "2026-08-18 16:11:27",
  "results": [
    {
      "name": "电压测量",
      "type": "measurement",
      "passed": true,
      "skipped": false,
      "state": "PASS",
      "detail": "",
      "duration": 0.5
    }
  ]
}
```

### 6.3 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| plan | string | 测试计划名称 |
| sn | string | SN 号（本轮被测产品） |
| station_id | string | **工位 ID**（产线系统设置中配置） |
| overall | bool | 本轮总体结果（`true`=通过） |
| total / passed / failed / skipped | number | 总用例 / 通过 / 失败 / 跳过 数量 |
| time | string | 上报时间 `YYYY-MM-DD HH:MM:SS` |
| results | array | 每个用例的完整结果数组（`name/type/passed/skipped/state/detail/duration` 及可能的 `sessions`/`measurements` 等） |

### 6.4 认证

若计划设置中 `server_username` / `server_password` 均非空，请求附带 **HTTP Basic Auth**（`requests` 的 `auth=(user, psw)`）；两者都为空则不认证。

### 6.5 响应

成功返回 2xx 即视为上报成功（产线端以 `resp.ok` 判断）。
