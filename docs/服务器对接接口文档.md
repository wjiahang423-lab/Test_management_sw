# 测试用例管理与执行软件 —— 服务器对接接口文档

版本：1.2
日期：2026-09-20
适用对象：服务器端开发人员（接收产线软件上报的数据）

---

## 1. 概述

产线端「测试用例管理与执行软件」（EOL）每轮测试结束后向服务器上报四类数据：

| 编号 | 数据类型 | 传输方式 | 场景 |
| --- | --- | --- | --- |
| 1 | 逐用例测试数据（JSON） | HTTP POST，`multipart/form-data`（`det_data` 字段值为 JSON 对象） | 每个测试用例一条记录（含 SN/批次/**工位ID**/判定标准/实际值等），入库用 |
| 2 | HTML 测试报告 | HTTP POST，`multipart/form-data` | 归档/人工查看用 |
| 3 | 运行日志（log） | HTTP POST，`multipart/form-data` | 与报告一起归档 |
| 4 | MES 结果汇总（JSON） | HTTP POST，JSON body | 向 MES 上报本轮整体结果（含工位ID） |

其中接口 1（JSON 上报）携带 **`stationId`**、接口 4（MES 上报）携带 **`station_id`**，
工位 ID 在产线软件的【系统设置 → 全局基础设置】中配置，标识数据来自哪个工位。

四个接口**相互独立**，在产线软件的【计划设置】里分别配置地址；任意一个失败都不影响产线本地测试流程，仅记录到执行日志（JSON 上报失败的数据会暂存本地，下次测试开始时自动续传）。

> 产线软件侧的判定规则：只要能收到 **HTTP 2xx** 响应即视为"上报成功"（`requests` 的 `resp.ok`）。
> 因此请务必对成功请求返回 2xx 状态码；建议同时返回 JSON 并附业务状态码（见各接口示例）。

---

## 2. 通用约定

- 字符编码：`UTF-8`。
- 时间格式：`YYYY-MM-DD HH:MM:SS`（本地产线时间），如 `2026-08-17 14:00:00`。
- 所有字段值可能包含中文，服务器按 UTF-8 解析。
- 各接口的 URL 均由产线端在计划设置中填写，服务器保证对应路径可访问即可。
- 上报密钥：逐用例 JSON 上报要求密钥（一个 SN 一组密钥）。产线端由**测试脚本**从产品/服务器获取后通过
  `set_upload_key(key)` 回填（未回填时回退使用计划设置的 `json_upload_key`），随上报报文 `det_data` 的
  `key` 字段发送；服务器据此校验归属。
- 认证：接口支持两种鉴权，可叠加使用——
  - **Token 认证**（`use_token_auth=true` 时启用，优先）：测试开始前产线端 `POST login_url`（`{username, password}`）
    获取 Token（依次取响应的 `token` → `access_token` → `data.token`），上报时请求头附带
    `token_header: token_prefix + Token`（默认 `Authorization: Bearer <token>`）；
  - **Basic 认证**：计划设置 `server_username` / `server_password` 均非空时，请求附带 HTTP Basic Auth，
    两者都为空则不认证。
- 失败暂存与续传：JSON 上报失败（非 2xx 或异常）时将数据暂存本地，每次测试开始时自动续传（详见 3.7）。

## 3. 接口一：逐用例 JSON 数据上报（数据入库）

### 3.1 请求

- **方法**：`POST`
- **URL**：产线【计划设置 → 逐用例 JSON 数据上报 → 上报接口地址】
- **Content-Type**：`multipart/form-data`（`requests` 自动设置）
- **频率**：每轮测试结束后上报一次（同一轮内所有用例在一次请求中一次性提交）

### 3.2 请求体（multipart/form-data）

表单字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| det_data | str | 检测数据，值为**真实 JSON 对象**（字段见 3.3），服务器需按 JSON 对象解析 |
| log_file | file | 本次测试日志文件（MIME `text/plain`），**仅检测失败（detResult=1）时上传**；正常时该字段不存在 |

> 正常（本轮全部执行用例都通过，detResult=0）时仅发送 `det_data`，不携带 `log_file`。

`det_data` 报文示例：

```json
{
  "key": "SECRET-KEY-001",
  "lineId": 1,
  "stationId": 1,
  "productSn": "SN-20260817-001",
  "batchId": 1001,
  "detTime": "2026-08-18 16:11:27",
  "deviceId": 0,
  "seriesId": 2,
  "detResult": 1,
  "dtcCode": "E1001",
  "caseNum": 10,
  "passNum": 9,
  "failNum": 1,
  "records": [],
  "isFinal": false,
  "finalBom": []
}
```

### 3.3 字段说明

**det_data 顶层字段：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| key | string | 否 | 上报密钥（脚本 `set_upload_key(key)` 回填，否则回退计划设置的 `json_upload_key`，可为空） |
| lineId | long | 是 | 产线 ID（【系统设置 → 全局基础设置 → 产线ID】） |
| stationId | long | 是 | **工位 ID**（产线系统设置中配置，标识数据来自哪个工位） |
| productSn | string | 是 | SN 号（本轮被测产品） |
| batchId | long | 是* | 批次号（计划设置中的"当前批次"，解析为 long，无法解析/为空时为 0） |
| detTime | string | 是 | 检测时间，格式 `YYYY-MM-DD HH:MM:SS` |
| deviceId | long | 是* | 检测终端 ID（预留，恒为 0） |
| seriesId | long | 是* | 产品系列 ID（计划设置，可空，为空时为 0） |
| detResult | int | 是 | 本轮总体判定：`0`=正常（所有执行用例全部通过），`1`=异常（含本轮没有实际执行用例的情况） |
| dtcCode | string | 是* | 故障码（detResult=1 时取计划设置的 `dtc_code`，正常时为 `""`） |
| caseNum | int | 是 | 执行用例数（不含跳过） |
| passNum | int | 是 | 通过用例数 |
| failNum | int | 是 | 失败用例数 |
| records | array | 是 | 用例结果记录数组，**每个执行的测试用例一条** |
| isFinal | bool | 是* | 是否总装线（计划设置） |
| finalBom | array | 是* | 总装线 BOM（`isFinal=true` 时上传，元素为 `{subSn, subLineId}`；否则为空数组） |

**records 元素：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| caseId | string | 是 | 用例 ID（缺省时回退为用例编号 `case_no`） |
| caseName | string | 是 | 测试用例名称（Loop 为用例名） |
| category | string | 是 | 用例类型：`action` / `delay` / `pop` / `measurement` / `loop` |
| standard | object | 是 | 判定标准（真实 JSON 对象），形如 `{"lower": 11, "upper": 13, "expected": "..."}`；`expected` 为字典时原样返回；无阈值时为 `{}` |
| actualInput | object | 是 | 实际输入/实际值（真实 JSON 对象）：Measurement/Loop 子项为 `{"values": [...]}` 或 `{"键": 值}`；Action 返回 dict 时为其负载；否则为 `{"value": 值}`；可为 `{}` |
| result | int | 是 | 该用例判定：`0`=通过，`1`=失败 |
| durationMs | int | 是 | 耗时（毫秒，取整） |
| testTime | string | 是 | 该用例测试时间，回退默认取顶层 `detTime` |
| deviceId | long | 是* | 检测终端 ID（预留，恒为 0） |
| curveData | object | 否 | **仅 Loop 类型存在**：`{"xAxis": "index", "yAxis": "value", "points": [...]}`，`points` 为该轮各子项实际测量点数组 |
| extrinsic / intrinsic / parameters | object | 否 | Action 脚本返回 dict 的同名键原样附带（如标定参数，见第 9 节） |

**各用例类型的 records 生成规则：**

| 用例类型 | records 条数 | 说明 |
| --- | --- | --- |
| Measurement | 一条 | `result` 按判定 0/1；各返回项实际值并入 `actualInput.values`，阈值并入 `standard` |
| Loop | 一条 | 父节点 `category=loop`、`result` 为用例整体；各子项测量点并入 `curveData.points`，实测值并入 `actualInput.values` |
| Action / Delay / Pop | 一条 | `result` 按执行结果 0/1；Action 返回 dict 时其 `extrinsic/intrinsic/parameters` 键原样附带 |

> \* 语义上允许为空或固定值，但字段本身始终存在（`""` / `0` / 空数组等）。

### 3.4 阈值上下限取值规则（standard 对象 lower/upper）

| 阈值写法 | lower | upper | 备注 |
| --- | --- | --- | --- |
| 单值固定值 `5` / `100` | 5 / 100 | 5 / 100 | 等于判定 |
| 范围 `11~13` 或 `11,13` | 11 | 13 | 范围内判定 |
| 大于 `200`（判定=大于） | 200 | null | 大于判定 |
| 小于 `0.5`（判定=小于） | null | 0.5 | 小于判定 |
| 非数值 `pass` / `fail` / `OK` | null | null | 无法数值化，实际值按文本上报 |

> 各用例类型的 records 生成规则见 3.3（Measurement / Loop / Action / Delay / Pop 各生成一条记录）。

### 3.5 认证方式

接口一同时支持 **Token 认证** 与 **HTTP Basic 认证**（可叠加）。

**Token 认证（`use_token_auth=true` 时启用，优先）：**

测试开始（执行用例前）产线端先调用登录接口换取 Token：

- **方法**：`POST`；**URL**：计划设置的 `login_url`
- **请求体**：`{"username": login_username, "password": login_password}`
- **响应**：产线端依次尝试从 `token` → `access_token` → `data.token` 提取 Token；均不存在则登录失败

登录成功后 Token 存入产线端运行时上下文，随后的上报请求头附带
`token_header: token_prefix + Token`（默认即 `Authorization: Bearer <token>`）。
取 Token 失败时上报回退到 Basic 认证（或进入 3.7 暂存续传）。

**Basic 认证：**

计划设置的 `server_username` / `server_password` 均非空时，请求附带 `requests.auth=(user, psw)`；
两者都为空则不做认证。

> 产线端以 **HTTP 2xx** 判断上报成功，认证失败请返回非 2xx 状态码。

### 3.6 响应

成功：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"code": 0, "message": "ok"}
```

建议：服务器收到并成功入库后返回 2xx；校验失败（如密钥错误、字段缺省）返回 4xx，并发可选地携带错误信息。产线端仅依据状态码判断成功与否并写入执行日志。

### 3.7 上报失败处理（暂存与续传）

- 上报请求返回非 2xx 或发生异常时，产线端把该轮的 `det_data`（含 key、日志文件路径）暂存到本地
  `data/pending_uploads/` 目录（文件名 `{计划名}_{SN}_{时间戳}.json`）。
- **每次测试开始**（执行用例前，且当前计划的逐用例 JSON 上报启用时）产线端自动检查该目录并续传上次未上报的数据。
- 续传报文最多重试 **3 次**（每次间隔 1 秒），仍失败则文件的 `retry_count` 加 1；
  同一文件累计重试 **3 次**仍失败后不再尝试。
- 过期的待上报文件按【系统设置】的「待上报数据保留天数」（`pending_retention_days`，默认 2 天）清理，
  优先以文件内 `create_time` 为准，缺失时用文件修改时间。

## 4. 接口二：HTML 报告上传

### 4.1 请求

- **方法**：`POST`
- **URL**：产线【计划设置 → 远程文件存储 → 上传服务器地址】
- **Content-Type**：`multipart/form-data`

### 4.2 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| report | file | HTML 测试报告文件（表单文件名 `report.html`，MIME `text/html`） |
| log | file | 运行日志文本文件（表单文件名 `<日志文件名>.log`，MIME `text/plain`） |
| plan | string | 测试计划名称 |
| sn | string | SN 号 |

> `report` 与 `log` 至少其一存在（上传内容由【远程文件存储 → 上传内容】决定，默认 `both`；仅需报告时产线端可不发 `log` 字段）。
> 若计划设置中 `server_username` / `server_password` 均非空，该请求同样附带 HTTP Basic Auth。

### 4.3 请求示例（curl）

```bash
curl -X POST http://192.168.1.100:8000/upload \
  -F "report=@示例测试计划_SN123_20260817_140000.html" \
  -F "log=@示例测试计划_20260817_140000.log" \
  -F "plan=示例测试计划" \
  -F "sn=SN123"
```

### 4.4 响应

成功返回 2xx 即可（如 `200 OK`）。可返回 JSON：`{"code": 0, "message": "ok"}`。

## 5. 接口三：运行日志上传

日志随报告一起以 `multipart/form-data` 上传（见接口二字段表 `log` 字段），**没有单独接口**。
产线端启用「远程存储报告和日志」后，报告与日志每次同时上传到同一个地址。

> 若需要把日志单独存储/单独接口，请与产线端确认；当前版本日志与报告统一按接口二处理。

## 6. 接口四：MES 结果上报（综合汇总）

### 6.1 请求

- **方法**：`POST`
- **URL**：由计划设置的 `mes_server` 与 `mes_interface` 组合而成：
  - 若 `mes_interface` 以 `http://`/`https://` 开头，则直接使用 `mes_interface`；
  - 否则为 `mes_server.rstrip("/") + "/" + mes_interface.lstrip("/")`。
- **Content-Type**：`application/json`
- **频率**：每轮测试结束后上报一次（汇总本轮整体结果）
- **触发条件**：产线端仅在计划设置 `storage_mode=remote` 时发送本上报；`mes_server` 为空则不发送。

### 6.2 请求体

```json
{
  "plan": "机器人下线测试",
  "sn": "SN-20260817-001",
  "station_id": "01",
  "overall": true,
  "total": 10,
  "passed": 9,
  "failed": 1,
  "skipped": 0,
  "time": "2026-08-18 16:11:27",
  "results": [
    {
      "index": 1,
      "case_no": "1-1",
      "name": "电压测量",
      "type": "measurement",
      "state": "PASS",
      "passed": true,
      "detail": "",
      "duration": 0.5
    }
  ]
}
```

### 6.3 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| plan | string | 测试计划名称 |
| sn | string | SN 号（本轮被测产品） |
| station_id | string | **工位 ID**（产线系统设置中配置） |
| overall | bool | 本轮总体结果（`true`=通过） |
| total / passed / failed / skipped | number | 总用例 / 通过 / 失败 / 跳过 数量 |
| time | string | 上报时间 `YYYY-MM-DD HH:MM:SS` |
| results | array | 每个用例的完整结果条目（`index/case_no/name/type/description/criterion/state/passed/detail/duration`；Loop 含 `sessions`，Action/Measurement 可能含 `payload`/`measurements`） |

### 6.4 认证

若计划设置中 `server_username` / `server_password` 均非空，请求附带 **HTTP Basic Auth**（`requests` 的 `auth=(user, psw)`）；两者都为空则不认证。

### 6.5 响应

成功返回 2xx 即视为上报成功（产线端以 `resp.ok` 判断）。

## 9. 接口一附加说明：结构化结果上报（如标定参数）

`Action` 用例的脚本函数若返回 **dict**（典型如地盘标定的 `collect_calib_result` /
`verify_and_save` 返回的外参矩阵、残差、阈值），该 dict 会：
- 显示在本地 HTML 报告的该用例下（「参数 / 值」子表）
- 在**接口一**（逐用例 JSON 上报）中随该用例记录附带，可入库保存

上报记录（records 元素，见 3.3）中，该 dict 整体作为 `actualInput`，且其中以下同名字段会
原样附加到记录顶层（其余键仅在本地 HTML 报告展示）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| extrinsic | object | 外参矩阵，形如 `{x, y, z, roll, pitch, yaw}` 或自定义键值 |
| intrinsic | object | 内参矩阵/内部参数 |
| parameters | object | 其它标定参数（残差、阈值等按脚本返回键值原样附带） |

示例（`Demo_接口测试` 计划的标定确认用例，省略部分顶层字段）：

```json
{
  "key": "SECRET-KEY-001",
  "lineId": 1,
  "stationId": 1,
  "productSn": "AGV-DEMO-001",
  "batchId": 0,
  "detTime": "2026-08-31 20:35:05",
  "records": [
    {
      "caseId": "1-2",
      "caseName": "Test2_查看截图并保存",
      "category": "action",
      "standard": {},
      "actualInput": {
        "rmse": 0.006,
        "threshold": 0.01,
        "passed": true,
        "note": "演示：雷达/相机轮廓重合 RMSE 低于阈值",
        "extrinsic": { "x": 0.0, "y": 0.0, "z": 0.05, "roll": 0.0, "pitch": 0.0, "yaw": 0.0 }
      },
      "result": 0,
      "durationMs": 500,
      "testTime": "2026-08-31 20:35:05",
      "deviceId": 0,
      "extrinsic": { "x": 0.0, "y": 0.0, "z": 0.05, "roll": 0.0, "pitch": 0.0, "yaw": 0.0 }
    }
  ]
}
```

> 标定原始结果文件（RK3588 标定算法落盘 JSON）可通过脚本 CONFIG 的
> `calib_input_file` 指定，脚本自动读取并合并进上报与报告。
