# 测试用例管理与执行软件 —— 软件说明文档（用户手册）

版本：1.4
日期：2026-08-17
开发技术：Python + PyQt5

---

## 1. 软件简介

测试用例管理与执行软件是一套面向产线/实验室的测试方案管理工具，支持：

- 多级测试计划管理：**测试计划（PLAN）→ 测试序列 → 测试用例**
- 五种用例类型：Action（仅执行）、Delay（延时）、Pop（人机交互）、Measurement（测量）、Loop（循环批量）
- 管理员 / 操作员两级权限控制，一键分权登录
- 生产统计看板（总数量 / 良品 / 良率 / 不良率，存储于 `data/stats.ini`，按日期分节）
- 本地 / 远程两种报告存储方式
- 产线触屏 **Kiosk 全屏模式**（F11 切换全屏），窗口底部状态栏实时显示设备电量/电源与 WiFi 信号强度
- **连续循环测试**（耐久测试）：一轮结束自动从头再执行，每轮实时计入生产统计
- 逐用例 JSON 数据上报（V1.4：`multipart/form-data` 的 `det_data` 报文，含每条用例结果 + 阈值与密钥；密钥由脚本 `set_upload_key` 回填）
- 上报失败**自动暂存**（`data/pending_uploads/`），下次测试启动时**自动续传**
- 脚本内置 API，可在测试脚本中直接调用

## 2. 运行环境与安装

### 2.1 环境要求

- Python 3.8+（开发环境为 3.10）
- 依赖包：PyQt5、PyYAML、requests

### 2.2 安装依赖

```bash
cd Test_management_sw
pip install -r requirements.txt
```

### 2.3 启动软件

```bash
python3 main.py
```

### 2.4 打包部署（产线平板/电脑）

正式产线使用推荐打包成独立程序（无需安装 Python），通过 `build_app.py` 生成：

```bash
python3 build_app.py        # 生成 dist/EOL/ 目录
```

> 也可以直接 `pyinstaller EOL.spec`（spec 文件路径基于自身位置解析，可在任意机器构建；
> 两者产物一致，按习惯选用其一）。

打包后目录结构：

```
dist/EOL/
├── EOL(.exe)               # 主程序（双击运行）
├── _internal/              # 打包内置的代码、UI、scripts、assets（只读，勿改动）
└── data/                   # 运行数据目录（可读写）
    ├── plans/              # 测试计划
    ├── logs/               # 运行日志与系统日志
    ├── reports/            # HTML 报告
    ├── pending_uploads/    # 上报失败暂存的待上报数据（下次启动自动续传）
    ├── ext_packages/       # 【外部扩展包目录】详见第 3 章
    ├── stats.ini           # 生产统计（按日期分节 total/pass/fail）
    ├── users.json
    ├── settings.json
    └── variables.json
```

> `data/` 目录与主程序同级，**升级/重新打包不会覆盖**（打包时不会清理 data/）。
> 跨电脑迁移时，只需拷贝整个 `dist/EOL/` 文件夹（或至少 `EOL` + `data/`）。

## 3. 外部扩展包（测试脚本的第三方依赖）

> 场景：`scripts/` 下的测试脚本可能用到第三方库（如 `paramiko`、`pyserial`、`numpy` 等）。
> 软件提供一套「外部扩展包」机制，让你可以在**打包后的产线电脑**上按需补充这些依赖，**无需重新打包**、不影响软件自身运行。

### 3.1 机制原理

- 软件在**每次加载测试脚本前**，自动把 `data/ext_packages/` 和 `scripts/` 目录加入脚本的 `sys.path`。
- 测试脚本里 `import xxx` 时，Python 会按 `sys.path` 顺序查找，因此放在 `data/ext_packages/` 下的任何包都能被脚本导入。
- 该目录位于可写的 `data/` 下，与打包的 `_internal/`（只读）隔离，因此：
  - 放包/删包**不需要重新打包**；
  - 软件自身的代码和内置依赖不受影响；
  - 升级软件（重新打包）也不会清掉这些包。
- `data/ext_packages/` 目录首次启动软件时自动创建，无需手动建。

### 3.2 打包时内置的依赖

默认打包会内置以下依赖（软件自身功能所需）：

| 依赖 | 用途 |
| --- | --- |
| PyQt5 | 界面 |
| PyYAML | 读取 Loop 用例 YAML 数据 |
| requests | 远程 MES 上报 / 远程文件上传 |
| paramiko | SSH / SFTP 远程部署（如 orin_3588_deployer.py 脚本） |

如果你要用的包属于上述之一，直接可用，无需额外操作。

### 3.3 在联网的开发电脑上准备好扩展包

在一台**能上网的电脑**（可以是开发机，或产线电脑临时联网）执行：

```bash
# 方式一：下载到指定目录（推荐，产物最干净）
pip download --only-binary=:all: --platform <平台> -d <下载目录> paramiko

# 方式二：用 --target 安装到一个临时目录（会解压成可直接拷贝的结构）
pip install --target <临时目录> pyserial numpy
```

> 注意 `<platform>` 要和产线电脑一致，例如：
> - Windows x64：`win_amd64`
> - Linux x64：`manylinux2014_x86_64` / `linux_x86_64`
> - Linux ARM64（RK3588 / Jetson）：`linux_aarch64`
>
> 跨平台拷贝 C 扩展包（如 `cryptography`、`numpy`）时，**必须下载与目标电脑相同的平台版本**，否则运行时报错。

### 3.4 移植到产线电脑的 data/ext_packages

产线电脑上打开打包程序目录，进入 `data/` 子目录（与 `EOL` 可执行文件同级）：

```
dist/EOL/data/ext_packages/
```

**方法一：U 盘 / 网络拷贝（离线方式，最常用）**
1. 在联网电脑上把第 3.3 节下载好的 `.whl` 文件，或 `--target` 解压出的包文件夹，拷贝到 U 盘。
2. 插到产线电脑，把内容复制到 `dist/EOL/data/ext_packages/` 下。

**方法二：产线电脑直接联网安装（若允许联网）**

在产线电脑的程序目录下执行：

```bash
cd dist/EOL/data/ext_packages
pip install --target . pyserial numpy
```

> `pip install --target .` 会把包解压到当前目录，结构即最终所需的目录结构。

**方法三：拷贝另一台电脑已有的环境（不推荐，易漏依赖）**

如果另一台电脑的 Python 环境里已装好这些包，可到其 `site-packages` 目录把**包文件夹及其依赖**拷贝过来；但 C 扩展包必须平台一致，且容易漏依赖，优先使用方法一/二。

### 3.5 校验是否成功

- 拷贝完成后，**重新启动软件**再执行相关测试脚本。
- 若脚本依赖未找到，会提示「加载脚本失败」并记录到系统日志 `data/logs/system_YYYYMMDD.log`，同时该用例判定为 FAIL。
- 也可以在脚本中主动判断并返回明确信息，例如：

```python
def ssh_check(params):
    try:
        import paramiko
        return {"value": paramiko.__version__, "pass": True,
                "message": "paramiko " + paramiko.__version__, "unit": ""}
    except ImportError:
        return {"value": "", "pass": False,
                "message": "缺少 paramiko，请放入 data/ext_packages/", "unit": ""}
```

### 3.6 注意事项

1. **必须与产线电脑平台一致**（尤其 C 扩展：numpy、cryptography、pyserial 等）。
2. `data/ext_packages/` 里不要放名为 `test_api`、`app`、`scripts` 的文件夹，以免干扰软件内置模块。
3. 同名的包，`data/ext_packages/` 下的优先级**低于**软件内置依赖，不会覆盖内置库。
4. 依赖之间有传递依赖（如 paramiko 需要 bcrypt / cryptography / pynacl），拷贝时要把它们一起放进去；用 `pip download` 时加 `-r` 依赖清单或直接下载完整包集合即可。

### 3.7 HTTP 接口测试（内置 requests）

软件已内置 `requests` 库（打包时自动包含），做 HTTP 接口测试**无需添加任何扩展包**，脚本中直接使用即可：

```python
import requests

def http_add(a: int, b: int):
    """调用远程接口做加法并返回结果"""
    resp = requests.post("http://192.168.1.50:8000/add",
                         json={"a": a, "b": b}, timeout=5)
    data = resp.json()  # {"code": 0, "sum": 7, ...}
    return {"sum": data.get("sum"),
            "pass": str(data.get("code")) == "0"}
```

使用方法：在【管理页面 → 测试计划 → 新增用例】中按 `Measurement` 类型配置：
- 脚本路径选择该 `.py` 文件，函数名选 `http_add`（自动解析参数 `a`、`b` 与返回值）
- 输入参数 `a`、`b` 填数值（来源选「值」），或来源选「变量」绑定全局变量
- 返回值判定：返回项 `sum` + 大于/等于 阈值；或返回项 `pass` + 等于 `True`

> 软件管理页【帮助】按钮内含完整说明（含「脚本用到的第三方库」章节），产线现场可随时查阅。

## 4. 登录与权限

### 4.1 登录页

启动后如需登录（见"一键分权"），出现登录窗口：

- 输入 **用户名**、**密码**
- 选择 **角色**（管理员 / 操作员），角色必须与账号一致，否则拒绝登录

### 4.2 默认账号

| 用户名 | 密码 | 角色 | 权限 |
| --- | --- | --- | --- |
| admin | admin | 管理员 | 全部功能（执行页 + 管理页） |
| operator | operator | 操作员 | 仅执行页面 |

| 功能 | 管理员 | 操作员 |

## 5. 执行页面（操作员核心页面）

页面分为：顶部标题栏（logo / 工位名称 / 时钟）、左侧（测试步骤树 + 执行日志）、右侧（产品信息 / 生产统计 / 总体状态 / 开始按钮）、底部机器人状态栏。

> 产线触屏模式（Kiosk）：窗口启动即**全屏**、无标题栏（无边框），系统顶栏与左侧坞自动隐藏；按 **F11** 切换全屏/退出（手动退出后 60 秒内不自动回全屏，便于维护）。窗口**底部状态栏**实时显示设备**电量/电源**与 **WiFi** 信号强度（每 5 秒刷新）。
> **管理员**在执行页右上角有【管理页面】按钮可进入管理页；另有隐藏快捷键：`Ctrl+M` 管理页（仅管理员）、`Ctrl+Shift+L` 重新登录、`Ctrl+Q` 退出。

### 5.1 基本操作

1. **选择测试计划**：点击"测试计划"输入框，自动弹出可选计划列表（位于 `data/plans/`），点击即可加载；也可选择"浏览其他位置..."。
2. **开始执行**：点击页面右下角大号【▶ 开始】按钮，测试自动开始运行。
3. **SN 由脚本输入**：页面不提供 SN 输入框，SN 由测试脚本调用 `set_sn_to_Panel(sn)` 写入，并实时显示在"产品信息"区的 SN 标签处（脚本未写入时显示 `--`）。

> 一轮测试运行结束后自动恢复【▶ 开始】按钮，可再次执行下一台。

### 5.2 测试步骤树

- 树分两级：**序列**（可展开）→ **用例**
- 每行显示：序号 / 测试项名称 / 类型 / 状态 / 耗时
- 实时状态：待执行 → 运行中 → **PASS / FAIL / 跳过**
- Loop 用例展开后逐组平铺显示每组 session 的结果

### 5.3 总体执行状态

- 页面右侧"总体执行状态"以大字号醒目显示 **PASS（绿）/ FAIL（红）**
- 状态持续显示，直到下一轮开始测试才更新

### 5.4 产品信息与机器人状态

- **产品信息区**显示：
  - **SN 码**：只读显示当前 SN（由脚本 `set_sn_to_Panel(sn)` 输入并实时刷新）
  - **测试计划**：点击输入框弹出可选项即可加载
  - **当前批次**（在【计划设置】中修改）、**测试节拍**（最近一轮实测耗时秒数）
- **开始按钮**：位于右侧面板底部，大号绿色【▶ 开始】，运行中显示"▶ 执行中..."并置灰
- 页面**底部机器人状态栏**显示**机器人状态**：温度 / 电流 / 电压 / 电池%，
  由测试脚本调用 `set_robot_temperature / set_robot_current / set_robot_voltage / set_robot_battery`
  或 `set_robot_status(...)` 实时刷新（未更新显示 `--`）
- 窗口**最底部状态栏**（Kiosk 模式）显示设备**电量/电源**与 **WiFi** 信号（读 Linux `/sys/class/power_supply`、`/proc/net/wireless`，每 5 秒刷新；无电池/无网时显示对应提示）

### 5.5 生产统计看板

| 指标 | 说明 |
| --- | --- |
| 总数量 | 当天累计测试产品数 |
| 良品数 / 不良品数 | 当天 PASS / FAIL 数量 |
| 良率 / 不良率 | 百分比 |
| 清零统计 | 需输入密码（初始 **0000**，可在系统设置修改），**只清空当天**数据 |

> 统计存储在 `data/stats.ini`，按日期分节累加（如 `[2026-08-14]`），页面只显示当天；
> 文件可用文本编辑器直接修改；不清零则历史数据一直保留。

### 5.6 日志面板

- 位于左侧测试步骤树下方，默认隐藏
- 点击【▼ 显示日志】展开实时日志（高度约为步骤区域的 1/5），可随时【清空日志】
- 展开日志后测试步骤区域自动缩小（约占 80%）

## 6. 管理页面（仅管理员）

左侧导航包含四个子页面：**测试计划管理 / 全局变量管理 / 系统设置 / 用户管理**。

### 6.1 测试计划管理

#### 层级结构
```
测试计划 PLAN（独立 .plan 文件）
  └─ 测试序列（可增删改）
       └─ 测试用例（一条序列下可添加数十条）
```

#### 工具栏
| 按钮 | 功能 |
| --- | --- |
| 新建计划 | 创建空计划 |
| 打开计划 | 打开已有 `.plan` 文件 |
| 保存 / 另存为 | 保存当前计划（另存可指定新路径） |
| 删除计划 | 删除当前计划文件 |
| 计划设置 | 单计划独立配置（见 6.2） |
| 调试执行 | 在管理页内直接执行当前计划（不入生产统计） |
| 切换执行页面 | 跳转到执行页面 |
| 帮助 | 内置 API 与变量使用说明 |

#### 编辑操作
- **新增序列**：选中计划 → 点击【+ 新增序列】输入名称。
- **新增用例**：选中目标序列 → 点击【+ 新增用例】→ 弹出用例编辑窗口。
- **编辑 / 删除**：选中树中节点后操作。

### 6.2 计划设置（单 PLAN 独立配置）

| 配置项 | 说明 |
| --- | --- |
| 循环测试模式（耐久测试） | 开关：勾选后一轮测试结束自动从头重新执行，直到手动停止或退出；<b>启用需输入授权密码</b>（密码不对外公开）。仅限特殊测试需求（如耐久测试）使用，产线日常测试请勿启用 |
| 存储模式 | 本地存储（保存日志+HTML报告）/ 远程存储（调用远端 MES 接口上报） |
| 本地日志/报告目录 | 可选，默认 data/logs、data/reports |
| 启用远程存储报告和日志 | 开关：开启后每轮测试结束把 HTML 报告与运行日志上传到服务器（见 11.1） |
| 上传服务器地址 | 接收上传的接口地址，如 `http://192.168.1.100:8000/upload`（仅启用开关后可填） |
| 上传内容 / 上传策略 | 内容：both（报告+日志）/ report_only / log_only；策略：always（每轮都传）/ on_failure（仅失败轮次上传） |
| 逐用例 JSON 数据上报「启用」 | 开关：开启后每轮测试结束把每个测试用例的结果打包上报（`multipart/form-data` 的 `det_data` 报文，见 11.3） |
| 上报接口地址 | 逐用例 JSON 上报接口地址，如 `http://192.168.1.100:8000/api/test_data` |
| 当前批次 / 产品系列ID（seriesId） | 上报 det_data 的 batchId / seriesId |
| 是否总装线（isFinal） | 勾选表示当前为总装线，上报 finalBom 数组；分装线不传 |
| 服务器用户名 / 密码 | HTTP **Basic 认证**（仅当用户名密码均非空时才附带认证头，见 11.3） |
| 启用Token认证（优先于基本认证） | 开关（use_token_auth）：勾选后启动测试先获取 Token，上报时按 `Token字段名/前缀` 放入请求头 |
| 登录接口地址 / 登录用户名 / 登录密码 | 获取 Token 的接口与账号（POST `{username,password}`，从响应 `token`/`access_token`/`data.token` 取 Token） |
| Token字段名 / Token前缀 | 请求头字段名（默认 `Authorization`）与值前缀（默认 `Bearer `） |
| MES服务器地址 / 交互接口 / 上报报文模板 | 远程 MES 汇总上报目标与报文格式（见 11.1） |
| 远程文件存储服务器地址 | 预留 |
| 远程数据库 IP / 目标数据表 | 预留 |

> 说明：本地仍会保留**当天**的报告与日志，过期文件自动清理（见 11.1）。逐用例 JSON 上报失败会暂存到 `data/pending_uploads/`，下次测试启动时自动续传（最多重试 3 次，见 11.3）。

### 6.3 用例编辑窗口

#### 通用配置（所有类型共有）
- **用例名称**
- **执行类型**：Action / Delay / Pop / Measurement / Loop
- **跳过此用例**：勾选后执行时不执行该用例，树与报告标记为「跳过」，不参与通过/失败统计、不影响总体结果
- **超时时间(ms)**：`-1` 代表无限等待
- **失败重试次数**
- **失败策略**：失败后暂停执行 / 失败后继续下一条

#### ① Action（仅执行）
- 脚本路径、目标函数名称（自动列出脚本函数）
- 仅执行函数，不做结果判定；报告记录函数名与类型

#### ② Delay（延时）
- 延时时长 + 单位（毫秒 / 秒 / 分钟）
- 执行受全局"速度系数"统一缩放

#### ③ Pop（人机交互弹窗）
- 弹窗标题、显示内容（长度不限）
- 按钮1（返回 True）/ 按钮2（返回 False）文本
- 结果可存入全局变量
- 模态阻塞：是（等待操作员点击）/ 否（超时自动继续）

#### ④ Measurement（测量）
- 显示内容、脚本路径
- 选择脚本后【加载函数】→ 选择函数 → 自动解析：
  - **输入参数表**：参数名 / 类型 / 值或绑定变量 / 来源（直接值 / 全局变量）
  - **返回值表**：返回项 / 类型 / 绑定变量 / 判定方式 / 阈值范围
- **判定方式**：等于 / 不等于 / 大于 / 小于 / 范围内（`lo~hi` 或 `lo,hi`）/ 包含 / 长度
- **阈值留空**：只记录返回值，不做判定
- **绑定变量可选**：填写后执行完自动把该返回项的值写入全局变量（不存在自动创建）；留空不影响判定
- **返回项取值规则**（见下"返回值为 list/dict 时"）

##### 判定阈值写法
| 判定方式 | 阈值写法 | 含义 |
| --- | --- | --- |
| 等于 / 不等于 | `10`、`pass`、`[10, 20, 30]`、`{"a":1}` | 标量比较；list/dict 支持 JSON 结构比较 |
| 大于 / 小于 | `200`、`0.5` | 数值比较 |
| 范围内 | `100~300` 或 `100,300` 或 `100，300` | 下限 ≤ 返回值 ≤ 上限 |
| 包含 | list：元素值；dict：键名；字符串：子串 | 判断存在性 |
| 长度 | `3`、`>2`、`>=3`、`<5`、`2~4` | list/dict 元素（键）个数比较 |

##### 返回值为 list / dict 时的处理
「返回项」决定取返回值中哪一部分：

| 返回类型 | 返回项写法 | 效果 |
| --- | --- | --- |
| 标量 | `return` | 直接用该值判定 |
| list / dict | `return` 或 `*` | 取**整个** list/dict 判定或绑定 |
| dict | 键名，如 `voltage` | 取 `ret["voltage"]` |
| dict 嵌套 | 点号路径，如 `nested.a.b` | 取深层值 |
| list | 下标 `0`/`1`/`2` | 取对应元素 |

> 例：函数返回 `{"temp":45, "voltage":12.5}` —— 判断温度>40：返回项 `temp` + 大于 + `40`；
> 把整个 dict 存入变量：返回项 `return` + 绑定变量 `whole_dict`（判定留空）。

#### ⑤ Loop（循环批量）
- YAML 数据路径、脚本路径、执行函数、解析函数（可选）、session 键名（默认 `sessions`）
- **session 键名以页面输入为准**（找不到时自动回退 sessions/items/data/tests/cases，顶层是列表则直接用）
- **YAML 两种格式**：
  - 扁平式：`{name, value, min_val, ...}` 整条即数据，函数自行判定（如 `measure(params)`）
  - 包装式：`{name, input: {...}, expected: {...}}`，expected 逐项判定
- **函数调用自适应**：单字典参数函数传整条 dict；多形参函数按键名传参；无参函数直接调用
- **判定三层**：页面覆盖配置优先 → expected 判定（`20~30` 自动按范围）→ 无 expected 时自动找返回值中 `pass/ok/result` 字段判定
- 执行页平铺展示每组结果，HTML 报告完整输出全部 session 数据

### 10.1 自描述测量 API（Loop 专用）

Loop 用例的脚本函数内可调用**软件内置 API**（`test_api`）写入本次 session 的自描述测量字段：
**实际值 `value`、期望值 `expected`、阈值上限 `upper`、阈值下限 `lower`、打印信息 `message`**
及判定 `pass/ok`。这些字段会**直接显示在报告中**，并**逐条上报到后端服务器**（无需再写 YAML 的 `expected`）。

常用 API（完整见本章开头表格）：

| 函数 | 用途 |
| --- | --- |
| `set_measure_result(value, expected, unit, upper, lower, message, passed)` | 一次写入全部字段 |
| `set_measure_value(value, unit)` / `set_measure_expected(expected)` / `set_measure_range(lower, upper)` / `set_measure_message(message)` | 分项写入 |
| `set_measure_field(key, value)` | 写入任意自定义键（如 `code`/`msg`） |
| `get_measure_value()` / `get_measure_expected()` / `get_measure_range()` / `get_measure_message()` | 读取字段 |
| `reset_measure_result()` | 清空（每个 session 执行前软件会自动清空） |

**生效条件 / 优先级：**
1. **页面「覆盖配置」输入的阈值优先**：配置了 `expected`（字典）时框架按 expected 逐键判定并逐键上报；
2. 页面/YAML 未配置 expected 时，使用 `set_measure_*` 写入的 `value/expected/upper/lower/message` 生成上报记录（整组一条）；
3. 脚本函数返回的 dict 与 API 字段并存时：返回 dict 优先，API 只填充缺失字段。

脚本函数示例：

```python
import test_api
import requests

def measure_http(params):
    resp = requests.post("http://" + params["url"],
                         json={"cmd": "list"}, timeout=5)
    body = resp.json()                 # {"code": 0, "msg": "ok"}
    code, msg = body.get("code"), body.get("msg")
    test_api.set_measure_value(msg, unit="cmd")
    test_api.set_measure_expected("ok")
    test_api.set_measure_field("code", code)
    test_api.set_measure_field("msg", msg)
    test_api.set_measure_message("%s: 响应 code=%s msg=%s" % (params["name"], code, msg))
    test_api.set_measure_result(passed=(code == 0 and msg == "ok"))
    return True                        # 返回体可随意，字段以 set_measure_* 为准
```

`scripts/demo_instrument.py` 中的 `measure_api_http` / `measure_board_list` / `measure_bsp_version` /
`measure_api_value` 为现成的自描述测量函数示例（内部即调用上述内置 API 并直接返回结果 dict），
Loop YAML 演示数据见 `scripts/demo_items.yaml` 的 `-api_http_` / `-api_board_` / `-api_value_` 节。

页面覆盖优先示例：在 Loop 用例【覆盖配置】加一行 `upper`（类型 float，值 `14.0`），
该上限会覆盖数据中的 `13.0`，参与判定并随结果上报。

## 11. 报告与数据存储

### 11.1 报告存储

- **本地模式（始终生效）**：每次运行生成 HTML 测试报告 + 运行日志
  - 默认目录：`data/reports/`、`data/logs/`（或计划设置中自定义的目录）
  - 文件名：`计划名_SN_时间戳.html` / `计划名_时间戳.log`
  - 报告内容：总体结果、通过/失败统计、每条用例的状态与详情、Loop 全部分组数据
- **本地按保留天数清理**：软件启动时与每轮测试结束后自动清理目录中**早于保留天数**的报告/日志文件（默认保留 1 天，即只保留当天；可在系统设置「报告保留天数」调整），避免长时间 7×24 运行撑满平板硬盘
- **远程文件存储（可选）**：在【计划设置】勾选"启用远程存储报告和日志"并填写上传服务器地址后，每轮测试结束自动把 HTML 报告与日志以 `multipart/form-data` 上传到该接口：
  - 字段：`report`（report.html）、`log`（日志文件），另附 `plan`、`sn`
  - 上传内容（both/report_only/log_only）与上传策略（always/on_failure）在计划设置中配置
  - 上传成功/失败均写入执行日志；失败不影响本地保存与测试流程
- **MES 远程模式**：存储模式选"远程"时，运行结束后额外 POST 上报结果数据到配置的 MES 接口：
  - `mes_server` 为空则不发送；接口地址 = `mes_interface`（若以 http 开头则直接使用）否则 `mes_server` + `/` + `mes_interface`
  - POST JSON：`{plan, sn, station_id, overall, total, passed, failed, skipped, time, results}`，Basic 认证

### 11.3 逐用例 JSON 数据上报

在【计划设置】勾选「逐用例 JSON 数据上报 → 启用」并填写**上报接口地址**后，每轮测试结束
自动把**每个测试用例的结果**以 `multipart/form-data` 上报到服务器（一轮一个 SN）。

> 请求为 `multipart/form-data`，表单字段：
> - `det_data`：检测数据（真实 JSON 对象值，见下方报文结构）
> - `log_file`：日志文件，**仅 `detResult=1`（测试失败）时上传**
>
> 认证方式（可叠加）：Token 认证（`use_token_auth` 开启时，启动测试先请求登录接口获取 Token，
> 上报请求头携带 `token_header: token_prefix + token`，默认 `Authorization: Bearer <token>`）；
> Basic 认证（`server_username`/`server_password` 均非空时附带的 HTTP Basic 认证）。
> 上报失败会重试 3 次（每次间隔 1 秒），仍失败则**暂存**到 `data/pending_uploads/`，
> 下次测试启动时**自动续传**（同一 SN 连日志一起补传）。

> 服务器侧对接的完整接口格式、字段定义与最小实现示例，见 `docs/服务器对接接口文档.md`。

**报文结构（det_data，接口 V1.4）：**

```json

  "lineId": 101,
  "stationId": 1,
  "productSn": "SN号",
  "batchId": 20260814001,
  "detTime": "2026-08-18 16:11:27",
  "deviceId": 0,
  "seriesId": 1001,
  "detResult": 0,
  "dtcCode": "",
  "caseNum": 2,
  "passNum": 2,
  "failNum": 0,
  "records": [
    {
      "caseId": "用例编号",
      "caseName": "电压测量",
      "category": "measurement",
      "standard": {"lower": 11.0, "upper": 13.0, "expected": "11~13"},
      "actualInput": {"values": [12.2]},
      "result": 0,
      "durationMs": 1234,
      "testTime": "2026-08-18 16:11:27",
      "deviceId": 0
    },
    {
      "caseId": "002",
      "caseName": "002_Orin状态读取",
      "category": "loop",
      "standard": {"expected": "code=0, msg=ok"},
      "actualInput": {"values": ["ok"]},
      "result": 0,
      "durationMs": 800,
      "testTime": "2026-08-18 16:11:27",
      "deviceId": 0,
      "curveData": {"xAxis": "index", "yAxis": "value", "points": [{"index": 1, "value": "ok"}]}
    }
  ],
  "isFinal": false,
  "finalBom": []
}
```

字段说明（V1.4）：
- `lineId`：产线ID，来自**系统设置**（`data/settings.json` 的 `line_id`）
- `stationId`：工位ID，来自**系统设置**；`productSn` 为当前 SN；`batchId`、`seriesId` 来自**计划设置**
- `detTime`：检测时间（`yyyy-MM-dd HH:mm:ss`）；`deviceId` 预留（0）
- `detResult`：**0=正常 / 1=异常**——所有已执行用例全部通过为 0，否则为 1（跳过的用例不计）
- `dtcCode`：故障码，仅 `detResult=1` 时取计划设置的 `dtc_code`
- `caseNum`/`passNum`/`failNum`：已执行用例总数 / 通过数 / 失败数
- `isFinal`/`finalBom`：总装线标识与 BOM（`isFinal=true` 时上传，元素 `{subSn, subLineId}`）

**records 生成规则：**
- 每条记录由框架 `_build_record()` 生成：`result`（0=通过 / 1=失败）、`durationMs`、`testTime`；
  `standard` 为**真实对象**（`lower`/`upper`/`expected`），`actualInput` 为真实对象（`values` 数组 /
  `{键:值}` / payload），均不序列化成字符串。
- Loop 用例：**父节点一条记录**，各组 session 的测量点合并为 `curveData.points`（真实数组，**仅在存在测量点时出现**）；
  若存在测量行，`actualInput.values` 记录各实际值。
- 脚本通过 `set_measure_*`/payload 写入的扩展字段（`extrinsic`/`intrinsic`/`parameters`）会并入对应记录。
- 密钥 `key`：脚本调用 `set_upload_key(key)` 回填到 `det_data["key"]`；脚本未设置时兼容旧计划字段 `json_upload_key`。
- **跳过的用例不进入 records**，也不计入 caseNum/passNum/failNum。
- 阈值（standard.lower/upper）取值规则（解析自判定阈值）：
  - 单值 `5` / `100`（等于判定）→ 上下限相同（5,5）
  - 范围 `11~13` 或 `11,13` → (11,13)
  - 大于 `200` → 下限 200；小于 `0.5` → 上限 0.5
  - 非数值（`pass` / `fail`）→ 上下限为空，实际值按文本上报
- 上传成功/失败写入执行日志；失败不影响本地保存与测试流程。

#### 想往 JSON 里加字段，改哪里？

上报 JSON 在**框架代码 `app/core/report.py`** 中生成，无需改测试脚本：

| 想加的内容 | 修改位置 |
| --- | --- |
| 每条记录增加字段 | `app/core/report.py` → `_build_record()` 的返回 dict（加一个键值对即可） |
| Loop 曲线点（`curveData.points`）增加字段 | `app/core/report.py` → `_build_record()` 里 `points.extend(...)` 追加的 dict |
| 顶层字段（如增加产线号） | `app/core/report.py` → `send_json_cases()` 里 `det_data = {...}` |
| 时间格式 | `app/core/report.py` → `_now_str()`（`detTime`，秒精度） |

示例：给每条记录加一个「产线号」字段，在 `_build_record()` 里加：
```python
rec = {
    "caseId": r.get("id", "") or r.get("case_no", ""),
    ...
    "product_line": "line-01",   # 新增字段，直接加在这里
}
```
Loop 曲线点加字段同理，在 `_build_record()` 的 `points` 追加处加键。

> 说明：报文字段以 `app/core/report.py` 中的实际代码为准；本小节只列常见结构。

## 12. 常见问题（FAQ）

**Q：启动后如何进入登录页？**
A：在【用户管理】页开启"一键分权"，重启软件即显示登录页。

**Q：忘记清零统计密码？**
A：初始为 `0000`，可在【系统设置】中修改。

**Q：脚本函数列表为空？**
A：确认脚本路径正确、脚本可被 Python 解析（无语法错误），且没有依赖未安装的库；脚本需要的第三方库请放入 `data/ext_packages/`（见第 3 章）。

**Q：Measurement 判定不通过？**
A：检查"判定方式"与"阈值/范围"格式：范围支持 `11~13`、`11,13`、`11，13` 三种写法；
list/dict 返回值需在"返回项"列填写正确（标量 `return`、dict 写键名、list 写下标）；
绑定变量留空也能正常判定（判定与绑定相互独立）。

**Q：返回值是 list 或 dict 时怎么判断？**
A：返回项填 `return`（或 `*`）取整个对象，判定方式可选：
等于/不等于（阈值写 JSON 文本）、包含（list 判断元素、dict 判断键）、长度（如 `>2`、`2~4`）；
也可只取其中一部分：dict 填键名（支持点号路径 `a.b.c`）、list 填下标（`0`/`1`/`2`）。

**Q：Loop 用例如何组织 YAML？**
```yaml
sessions:
  - name: "测试点1"
    input: {voltage: 12.0, current: 1.5}
    expected: {result: "pass", max_temp: 60}
```

**Q：停止执行会计入生产统计吗？**
A：不会，手动停止的运行不计入统计，避免误判不良。

**Q：如何让脚本自己弹窗获取 SN？**
A：脚本内调用 `set_sn_to_Panel(sn)` 即可把 SN 传给软件。

**Q：把测试计划拷到另一台电脑/平板后，脚本找不到路径？**
A：计划保存时脚本与 YAML 路径会自动转成相对软件根目录的相对路径（如 `scripts/demo_instrument.py`），打开时自动识别根目录解析；若解析的绝对路径不存在，还会按文件名在根目录 `scripts/` 下回退查找。请把脚本放到程序目录下的 `scripts/` 文件夹，然后连同 `scripts/`、`data/plans/` 一起拷贝即可。

**Q：脚本用到第三方库（如 paramiko / pyserial / numpy），打包程序里没有，怎么办？**
A：把对应包放到打包程序目录的 `data/ext_packages/` 下即可，无需重新打包。详见第 3 章「外部扩展包」：下载 → 拷贝到 `data/ext_packages/` → 重启软件。

**Q：脚本在打包电脑上能跑，拷到另一台电脑后报"模块找不到"？**
A：说明该依赖没有随程序打包，也没有放入目标电脑的 `data/ext_packages/`。且第三方库需与目标电脑平台一致（如 Linux ARM64 与 x86_64 的 C 扩展包不通用），详见 3.3/3.4。

**Q：跑了很多天，报告和日志会越积越多占满硬盘吗？**
A：不会。软件本地会按保留天数自动清理旧报告与日志（默认只保留**当天**，启动时和每轮测试结束后自动清理早于保留天数的文件，可在系统设置「报告保留天数」调整）；如需长期归档，请在【计划设置】中开启"远程存储报告和日志"并配置上传服务器。

**Q：远程存储报告和日志需要搭什么服务？**
A：任意能接收 `multipart/form-data` 上传的 HTTP 接口即可。请求含字段 `report`（HTML 报告）、`log`（运行日志）以及 `plan`、`sn`，可用 Flask / FastAPI / Nginx(upload) 等实现，详见 11.1。

**Q：如何把每个测试用例的结果数据（SN/批次/实际值/阈值）上报到服务器？**
A：在【计划设置 → 逐用例 JSON 数据上报】勾选「启用」并填写上报接口地址。每轮测试结束自动以 `multipart/form-data` 上报（`det_data` 表单字段），`records` 数组里每个已执行用例一条记录（含 caseId/caseName/category/standard/actualInput/result 等）。字段与报文结构见 11.3。上报密钥由脚本调用 `set_upload_key(key)` 回填。

**Q：JSON 上报里阈值上下限是怎么算的？**
A：单值固定值（等于）上下限相同；范围 `11~13` 或 `11,13` 取上下限；大于只给下限、小于只给上限；非数值（如 pass/fail）上下限为空，实际值按文本上报。上下限写入 `records[].standard.lower/upper`。详见 11.3。

**Q：Loop 用例怎么上报？阈值从哪来？**
A：Loop 用例在 `records` 里是**父节点一条**（`category=loop`、`result` 为整体结果），各组子项数据合并为 `actualInput.values` 与 `curveData.points`（真实数组），阈值写入 `standard`。子项实际值取解析结果中对应字段的值，阈值上下限按 11.3 的规则解析（数值固定值 / `20~30` 范围 / 非数值为空）。
