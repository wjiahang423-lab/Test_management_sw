## 3. 核心数据流

```
main.py
  └── bootstrap() → RuntimeContext + Managers
       └── MainWindow
            ├── ExecutePage (操作员页)
            │    └── EngineWorker (QThread) ← 异步执行测试
            │         ├── _handle_action()   → load_function() → func()
            │         ├── _handle_delay()    → sleep(ms)
            │         ├── _handle_pop()      → signal → PopDialog → Event
            │         ├── _handle_measurement() → judge(value vs threshold)
            │         └── _handle_loop()     → YAML → per-session execution
            │
            └── ManagePage (管理员页)
                 ├── Plan CRUD
                 ├── Case Editor (case_form.py)
                 ├── Settings (全局+计划)
                 ├── Users & Variables
```

## 6. 常见故障排查路径

### 6.1 软件闪退/崩溃

```
1. 检查崩溃标记：
   ls -la data/logs/.prev_crash data/logs/crash_*.txt
   → .prev_crash 存在 = 上次异常退出（启动时会弹窗）；crash_*.txt 为原生崩溃转储

2. 查看系统日志：
   cat data/logs/system_YYYYMMDD.log

3. 查看运行日志最后100行：
   tail -100 data/logs/执行日志.log

4. 检查 Qt 平台插件错误：
   确保 DISPLAY 变量已设置（VNC/x11vnc 运行中）
   grep "xcb\|eglfs\|platform" data/logs/system_*.log
```

> 崩溃防护机制（main.py）：全局异常/线程异常/Qt 消息 handler 全部接入系统日志；
> faulthandler 把 SIGSEGV/SIGABRT 等原生崩溃转储为 crash_*.txt；`.prev_crash` 标记
> 上次非正常退出，下次启动弹窗提示，绝不静默闪退。

### 6.2 测试用例 FAIL

```
1. 从运行日志查找具体失败信息：
   grep "结果：FAIL" data/logs/执行日志.log

2. 常见原因：
   - mock服务器(code=-1) → 检查网络连通性：ping 10.5.35.49
   - 脚本不存在 → 检查脚本路径是否在 scripts/ 目录
   - 函数未找到 → 检查脚本中函数名是否正确
   - 超时 → 检查 timeout_ms 配置是否合理
```

### 6.3 脚本加载失败

```
1. 查看 last_load_error：
   grep "加载脚本失败\|未找到函数" data/logs/执行日志.log

2. 脚本缓存问题（修改脚本后不生效）：
   → 重启软件（清除 _module_cache）

3. 路径问题：
   → 检查 .plan 文件中脚本路径是否为相对路径
   → resolve_root_path() 优先查 BASE_DIR/scripts/
```

### 6.4 报告未生成/计数不对

```
1. 检查 cleanup_old_reports 是否正常：
   grep "cleanup\|清理" data/logs/system_*.log

2. 检查 reports 目录：
   ls data/reports/ | wc -l
   find data/reports/ -name "*.html" -mtime +0 | wc -l  # 旧报告数

3. stats.ini 与 reports 数量不一致是正常的：
   → stats.ini 记录的是测试轮次（每轮1份报告）
   → reports 目录每日清理只保留当天
```

### 6.5 内存/CPU异常

```
1. 检查进程状态：
   ps -p $(pgrep -f EOL) -o pid,rss,pcpu,etime,comm

2. 检查文件描述符泄漏：
   ls /proc/<pid>/fd | wc -l

3. 检查 monitor.log（如果有远程监控）：
   grep "rssKB\|crash" data/logs/monitor.log
```

### 6.6 远程设备连接问题

```
1. SSH连接：
   sshpass -p '111111' ssh user@10.5.33.219

2. VNC连接：
   端口 5900（x11vnc :0）

3. 检查 EOL 进程是否运行：
   ps aux | grep EOL
   systemctl status eol.service
```

### 7.2 部署到 Pi（10.5.35.49）

> PyInstaller 不可交叉编译：开发机(x86)打的 onedir 无法在树莓派(ARM)运行，需推源码在树莓派本机打包。

```bash
# 方式A（推荐）：推源码 -> 树莓派本机打包 aarch64 onedir + eol-cit.service 自启
./deploy/push_source_to_pi.sh 10.5.35.49 pi raspberry on onedir

# 方式B：推源码 + apt 装依赖，直接源码运行 + 自启
./deploy/push_source_to_pi.sh 10.5.35.49 pi raspberry on source

# 方式C：推送预打的 CIT 部署包（已存在 deploy/EOL_CIT.tar.gz 或 dist/EOL_CIT）
./deploy/push_to_pi.sh 10.5.35.49 pi raspberry on
```

参数格式：`IP 用户 密码 [on|off]`（依赖 `sshpass`：`sudo apt install sshpass`）。

  "settings": {

**上报鉴权要点（两套认证可叠加，见 report.py / engine.py）：**
- Basic 认证：`server_username`/`server_password`（默认 root/root）非空即附带 `requests.auth`。
- Token 认证：`use_token_auth=true`（布尔，从 plan 文件读取，未写入默认字段清单）时，启动测试先 `_login_for_token()` POST `login_url` 取 Token 存入 context；上报请求头用 `token_header: token_prefix+token`（默认 `Authorization: Bearer <token>`）；Token 获取失败/续传失败回退 Basic。
- 续传：上报失败 → `save_pending_data()` 暂存 `data/pending_uploads/{plan}_{sn}_{ts}.json`（含 key/log_path）；每次测试开始 `_retry_pending_uploads()` 重试（3 次、间隔 1s），仍失败更新 retry_count，≥3 次跳过；`cleanup_old_pending()` 按 pending_retention_days 清理。
- 密钥：脚本 `set_upload_key(key)` 回填（`context.get_upload_key()`），否则回退 `plan.json_upload_key`，放入 det_data["key"]。

## 11. 测试脚本编写规范

测试脚本位于 `scripts/` 目录，通过 `.plan` 文件引用：

```python
# 示例：scripts/pi_mock/pi_mock.py

def measure_pi(path: str = "/api/voltage", base: str = "http://10.5.35.49:5000") -> dict:
    """测量接口返回值。
    
    Args:
        path: API路径
        base: 服务器地址
    
    Returns:
        {"value": float, "unit": str, "code": int}
    """
    import requests
    r = requests.get(f"{base.rstrip('/')}{path}", timeout=5)
    data = r.json()
    return {"value": data.get("value"), "unit": data.get("unit", ""), "code": data.get("code", 0)}
```

**规范要点：**
1. 函数名需在 plan 的 `config.function` 中声明
2. 返回 dict 时，key 会与 plan 中 `returns[].item` 匹配
3. 可通过 `test_api.log(msg)` 输出日志
4. 可通过 `test_api.set_sn_to_Panel(sn)` 设置SN
5. Loop 脚本支持 YAML 数据驱动
