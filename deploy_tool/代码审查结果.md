  📋 代码审核报告

  一、项目总体评价

  这是一个产线机器人 EOL 测试管理系统，使用 PyQt5 + Python，架构清晰：main.py → bootstrap → MainWindow → ExecutePage/ManagePage，核心执行引擎 EngineWorker
  在 QThread 中异步运行，通过信号与 UI 解耦。日志和报告体系完善，支持本地/MES/JSON 多路上报。整体工程质量中上，以下列出具体问题。

  # 文件末尾内容明显断裂，TYPE_NAMES 和 SUPPORTED_TYPES 被拆开

  三、🟡 中等问题（建议修复）

  5. _plan_search_dirs 硬编码默认目录

  def _plan_search_dirs(self):
      dirs = [PLANS_DIR]   # data/plans/ 硬编码在项目根
  打包后 PLANS_DIR = os.path.join(BASE_DIR, "data", "plans")，若打包目录结构变化会找不到计划文件，且无用户提示。

  6. 计划文件路径回退逻辑过于乐观

  resolve_root_path() 当绝对路径不存在时，会在 scripts/ 目录下盲找同名文件（第 89-92 行），可能导致错误脚本被意外加载。

  7. 脚本缓存使用 hash() 作键，跨进程不稳定

  spec = importlib.util.spec_from_file_location(
      "_test_script_" + str(abs(hash(script_path))), script_path)
  Python 的 hash() 默认有随机化（PYTHONHASHSEED），同一脚本在不同次运行中缓存不命中，导致反复重新加载。应用确定性哈希如 hashlib.md5()。

  8. sys.path.insert(0, ...) 污染全局搜索路径

  script_loader.ensure_runtime_paths() 每次 import 都修改 sys.path，且有双检查但非原子操作。多个工程共用同一 Python 环境时会冲突。应使用
  importlib.util.spec_from_file_location + sys.modules 注册，而非挂到 sys.path。

  9. 连续模式内存泄漏风险

  # engine.py _run_plan()
  self.results = round_results   # 仅保留本轮
  虽然有意限制增长，但若 _do_report 抛异常，self.results 不会被更新，下轮 round_start 将基于错误的 len(self.results) 计算，造成数据遗漏。

  10. _wait_with_control / _wait_pause 轮询间隔不统一

  暂停/停止等待用 sleep(0.05)，超时等待用 sleep(0.02)，行为不一致，统一为 20~50ms 并文档化。

  五、架构亮点 ✅

  1. 执行引擎与 UI 完全解耦：通过 pyqtSignal 通信，EngineWorker 不引用任何 Qt Widget
  2. 崩溃标记机制：.prev_crash 文件 + 启动时提示，避免静默闪退
  3. Kiosk 全屏守护：_kiosk_timer 每 800ms 检测窗口状态，防止误触还原
  4. 脚本类型自适应传参：_adapt_loop_call 兼容无参/单参/多参多种签名
  5. RunLogger 线程安全：RLock + 异常保护，日志写入不影响主流程
  6. 轮次报告隔离：连续模式下 self.results = round_results 控制内存增长
