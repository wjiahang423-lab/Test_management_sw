## 2. 结论

1. “使能”前置是必要的：未使能时右臂驱动存在 `0x7500` 故障；`cia402_tools -m 8`
   后 14 个手臂驱动全部 `0x1237`。
2. 主站、伺服层、控制器都能启动；伺服层能 attach 共享内存。
3. 但伺服层读取手臂状态字出现 `0x0000 / 0x1237` 交替，并报腰部 slave 15/16
   模式切换超时，随后一直停在 `Enter into Waist Control`，没有发布关节数据。
4. `robot_app` 因拿不到组件/关节数据，`/zioneer/mc/action` 没有 action server，
   所以无法安全执行 `mc.arm.small_angle`。

## 3. 建议排查（不改机器人程序）

- 核对主站 `QUALITY_INSPECTION.xml` 的从站顺序与伺服层期望是否一致：
  当前链首有 2 个 FCE1100（`0:0`、`0:1`），手臂 ROKAE 从 `0:2` 开始；
  伺服层报的腰部 slave 15/16 与实际 TC600E 的 `0:16/0:17` 存在偏移迹象。
- 核对主站二进制与伺服层二进制版本是否配套（现场：主站 10-16，伺服层 10-13）。
- 检查腰部两个 TC600E 驱动的使能/模式（本次 p16/p17 一度为 `0x0250`）。
- 以上确认后再运行 `mc.arm.small_angle`；本次未发送运动指令。

## 5. 2026-11-04 追加：0x1240 状态处理

- 使能前的状态抓取现在接受：`0x0250 / 0x1208 / 0x1240 / 0x1237`。
- 现场读到 `0x1240` 时，`wait_motors_status_word` 会自动重启主站：
  1. `etherkit_master.stop_master()` 关闭旧主站会话；
  2. 兜底按进程名 `zioneer_etherkit` 逐级 `INT -> TERM -> KILL`，确保旧主站退出；
  3. `etherkit_master.start_master()` 用 `arm_interface.yaml` 的
     `master.precheck_config`（即 `QUALITY_INSPECTION.xml`）重新启动主站；
  4. 等待 `/dev/shm/pdo_shared_mem` 重新出现并 `chmod 666`。
- 只重启一次，避免 0x1240 持续存在时死循环；重启后继续等待其余状态字。
- 计划 `15040` 的“等待手臂驱动初始化”已改为该精确检查：
  `expected=0x0250,0x1208,0x1240,0x1237`、`timeout=60`、`restart_on=0x1240`，
  用例超时 120s。
