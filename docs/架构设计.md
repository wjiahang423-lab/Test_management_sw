# 测试用例管理与执行软件 —— 架构设计文档

版本：1.3
日期：2026-09-20
技术栈：Python 3.10 + PyQt5 + PyYAML + requests + paramiko + zlgcan

---

## 1. 设计目标

| 目标 | 说明 |
| --- | --- |
| UI 与逻辑分离 | 所有页面通过 `QtUiLoader` 加载 `.ui` 文件，业务代码零侵入 UI 定义 |
| 7×24 稳定运行 | Qt 主线程只负责渲染，测试任务全部在 QThread + 线程池中异步执行 |
| 界面不阻塞 | 工作线程严禁直接操作 UI 控件，一律通过信号槽 / 信号桥跨线程通信 |
| 全链路异常捕获 | 脚本执行、网络请求、文件读写、外部函数调用均带 try-except，异常只记日志不崩溃 |
| 内存泄漏防范 | 每次运行独立线程池并显式 shutdown；脚本模块按 mtime 缓存与失效 |

## 3. 核心模块设计

### 3.1 数据模型层（plan_model.py）

```

 ├── name / description

  │    ├── storage_mode      # local / remote
  │    ├── batch             # 当前批次
  │    ├── log_dir, report_dir
  │    ├── continuous        # 循环测试模式（一轮结束自动从头再执行）
  │    ├── remote_storage_enabled / remote_storage_url   # 报告+日志文件上传
  │    │    ├── remote_storage_content   # both / report_only / log_only
  │    │    └── remote_storage_strategy  # always / on_failure
  │    ├── json_upload_enabled / json_upload_url / json_upload_key  # V1.4 逐用例 JSON 上报
  │    │    ├── series_id / is_final，亦可读 dtc_code / bom_list
  │    ├── server_username / server_password   # HTTP Basic 认证
  │    ├── login_url / login_username / login_password  # Token 认证登录
  │    │    └── token_header(Authorization) / token_prefix(Bearer )
  │    ├── mes_server / mes_interface / mes_template
  │    ├── remote_file_server
  │    └── remote_db_ip / remote_db_table
  └── sequences[]            # 测试序列
      ├── id / name
      └── cases[]           # 测试用例
           ├── id / case_no / name / type(5类) / description
           ├── timeout_ms(-1 无限) / retry / skip
           ├── fail_policy (pause / continue)
           └── config{}     # 类型私有配置（见 3.2）
```

持久化：每计划独立 JSON 文件，`to_dict / from_dict / save / load`，扩展名 `.plan`。

### 3.2 五类用例配置结构（config）

| 类型 | 关键字段 |
| --- | --- |
| action | script, function, description |
| delay | delay_ms, description |
| pop | title, content, btn_true, btn_false, result_var, modal |
| measurement | display, script, function, params[], returns[] |
| loop | yaml_path, script, function, parser, session_key, overrides[] |

measurement 参数结构：`{name, type, value, source(value/variable)}`
measurement 返回结构：`{item, type, bind_var, judge(等于/不等于/大于/小于/范围内/包含/长度), threshold}`；item 支持点路径 `a.b.c` 与列表下标，空 / `*` / `return` 取整体返回值。
loop 覆盖结构：`{item, type, value}` —— 页面覆盖优先于 YAML，未配置则使用 YAML 定义。

### 3.3 执行引擎（engine.py）—— 核心并发设计

```
┌──────────────┐         信号(sig_*)          ┌──────────────────┐
│  GUI 主线程   │ ◄────────────────────────── │  EngineWorker     │
│  ExecutePage │                            │  (QThread.run)    │
│  (渲染/响应)  │ ────── 控制调用 ────────────► │  pause/resume/stop│
└──────────────┘                            └────────┬─────────┘
                                              │ 线程池 submit
                                              ▼
                                   ┌──────────────────────┐
                                   │ ThreadPoolExecutor    │
                                   │ (max_workers=4)       │
                                   │ 执行外部脚本函数       │
                                   └──────────────────────┘
```

**关键设计决策：**

1. **引擎生命周期**：每次运行创建一个新的 `EngineWorker`（QThread），`run()` 内置 stop/pause/sn/pop 四个 `threading.Event` 握手点，运行结束显式 `ThreadPoolExecutor.shutdown()`。
2. **跨线程通信**：
   - 引擎 → UI：`pyqtSignal`（sig_log / sig_case_state / sig_case_sessions / sig_overall / sig_progress / sig_run_started / sig_run_finished / sig_wait_sn / sig_request_pop / sig_reset_tree / sig_phase / sig_round_started / sig_round_finished）。
   - UI → 引擎：方法调用（pause / resume / stop）+ Event 唤醒。
3. **Pop 人机交互握手**：
   ```
   引擎线程                          GUI 线程
   emit sig_request_pop(config) ──► 弹出 PopDialog.exec_()
   阻塞等待 pop_requested          ◄── 点击后 set pop_result + pop_requested
   读取 pop_result 继续
   ```
4. **SN 等待握手（引擎保留能力）**：`wait_sn=True` 时引擎发 `sig_wait_sn` 并阻塞在 `sn_event` 上等待唤醒；当前执行页已改为关闭该握手（`wait_sn=False`，SN 输入框已移除），SN 由脚本经 `test_api.set_sn_to_Panel(sn)` 输入并显示到报告与页面；调试运行直接用固定"调试SN"。
5. **日志桥（LogBridge）**：脚本内 `log()`/`emit_log()` 可能在任意工作线程调用，统一经 `LogBridge.sig_log`（`pyqtSignal(str)`）队列到 GUI 线程再写 QTextEdit，杜绝跨线程操作 UI。
6. **超时与暂停协同**：`_wait_with_control(future, timeout)` 循环轮询 future 状态，同时响应 pause/stop，避免"暂停了函数仍在跑"或"超时失效"。
7. **延时调速**：`_speed_ms(ms)` 将延时按全局"速度系数"统一缩放。
8. **判定逻辑**：`_compare()` 支持数值/字符串/结构（list/dict）多套路径与「等于/不等于/大于/小于/范围内/包含/长度」判定；阈值 `20~30`/`20,30`/单值因判定方向由 `_threshold_bounds()` 解析出（下, 上）；阈值优先页面，其次 YAML；Loop 无 expected 时按返回中的 pass/ok/result/status 等字段自动判定。
9. **连续循环模式（continuous）**：`_run_plan()` 内层 `while` 循环连续执行多轮，无需重建 QThread；每轮开始发 `sig_round_started(round_no)`（页面清空日志只显示当前轮）、结束发 `sig_round_finished(ok, round_no)`（页面实时计入生产统计）并为该轮单独生成报告；仅保留最近一轮 results，防止连续长跑内存无界增长。
10. **启动鉴权与续传**：`run()` 进入用例循环前，若启用 Token 认证先 `_login_for_token` 请求登录 Token 存入上下文，随后 `_retry_pending_uploads()` 续传上次失败暂存的数据。

### 3.4 运行时上下文与内置 API（context.py + api.py）

`RuntimeContext` 用 `threading.RLock` 保护当前 SN、当前/上一次结果、总体结果、显示信息，供 GUI 与工作线程并发读写。

**内置 API（脚本可直接使用，或 `import test_api`）：**

| 函数 | 说明 |
| --- | --- |
| set_sn_to_Panel(sn) | 脚本把 SN 传给软件，显示到报告与执行页面 |
| get_sn() | 读取当前 SN（脚本输入） |
| get_test_result() | 当前用例结果 True/False |
| get_last_test_result() / get_last_test_detail() | 上一用例结果与详情 |
| set_display_info(k, v) / get_display_info(k) | 执行页面额外显示信息 |
| log(msg) | 输出到执行日志（线程安全） |
| get_variable(name) / set_variable(name, value) | 读写全局变量 |
| set_robot_status(**kwargs) / set_robot_temperature/current/voltage/battery / get_robot_status(key) | 读写机器人状态（温度/电流/电压/电池），随运行日志与报告记录 |
| set_measure_result(value, expected, unit, upper, lower, message, passed) 及 set_measure_value/expected/range/message/field、get_measure_*、reset_measure_result | Loop 会话自描述测量字段，合并进该 session 结果，随报告展示并逐条上报 |
| set_upload_key(key) / get_upload_key() | 逐用例 JSON 上报密钥（脚本回填后放入上报报文 key 字段） |
| get_station_id() / get_station_name() | 工位 ID（上报后端 stationId）与工位名称（页面显示） |

`api.py` 在 import 时注册惰性 `test_api` 模块（PEP 562 `__getattr__`），即使未初始化脚本也可被加载；`register_api()` 在启动时注入真实实现，`script_loader` 同时把 API 注入脚本模块命名空间，`list_functions` 自动过滤内置 API 名。

### 3.5 脚本加载与签名解析（script_loader.py）

- `importlib` 动态加载 `.py`，按 **路径 + mtime** 缓存，脚本修改后自动重新加载。
- `inspect.signature` 解析函数参数、默认值、返回注解，自动推断类型 `int/str/float/list/dict`。
- 类型推断优先级：**类型注解 > 默认值实例类型 > str**。
- Measurement/Loop 表单据此自动填充参数表与返回表。
- **外部扩展包机制**：`ensure_runtime_paths()` 在首次加载脚本前自动把 `data/ext_packages/` 与 `scripts/` 加入 `sys.path`，因此产线电脑可往 `data/ext_packages/` 里按需放入第三方包（如 pyserial / numpy）而**无需重新打包**；requests/PyYAML/paramiko 等软件内置依赖始终可用。

### 3.6 报告与存储（report.py）

- **本地模式**：每次运行生成 HTML 报告（含 Loop 全部分组 session 明细）+ 运行日志，保存到计划配置目录（默认 `data/reports`、`data/logs`），文件名带计划名 + SN + 时间戳；报告/日志按 `report_retention_days`、待上报数据按 `pending_retention_days` 自动清理。
- **远程文件存储**：`upload_reports` 用 `multipart/form-data` 上传 HTML 报告 + 运行日志（report/log 字段，另附 plan/sn）；按 `remote_storage_content`（both/report_only/log_only）与 `remote_storage_strategy`（always/on_failure）决定上传内容与时机。
- **逐用例 JSON 上报（V1.4）**：`send_json_cases` 在每轮测试结束后 POST 到配置接口，`multipart/form-data`，字段 `det_data`（真实 JSON 对象，不序列化为字符串）+ `log_file`（**仅 detResult=1 失败时**附带日志文件）。det_data 含 `lineId / stationId / productSn / batchId / detTime / deviceId / seriesId / detResult / dtcCode / caseNum / passNum / failNum / records[] / isFinal / finalBom[]`，上报密钥 `key` 由脚本 `set_upload_key` 回填、否则回退 `json_upload_key`；records 元素含 `caseId/caseName/category/standard(对象)/actualInput(对象)/result/durationMs/testTime/deviceId`，Loop 附加 `curveData{points}`，Action payload 附加 extrinsic/intrinsic/parameters。
- **鉴权（两种，可叠加）**：启用 `use_token_auth` 时引擎启动先 `_login_for_token`（`login_token` POST login_url `{username,password}`，从 token/access_token/data.token 取值）存入上下文，上报请求头带 `token_header: token_prefix+token`（默认 `Authorization: Bearer <token>`）；`server_username`/`server_password` 均非空时另附 HTTP Basic 认证。
- **失败暂存与续传**：上报失败/异常经 `save_pending_data` 存 `data/pending_uploads/{plan}_{sn}_{ts}.json`（含 plan_name/sn/create_time/retry_count/data/key/log_path）；每次测试开始引擎 `_retry_pending_uploads` 先续传，`_send_with_retry` 重试 3 次每次间隔 1s，仍失败再暂存并累计 `retry_count`；`cleanup_old_pending` 按保留天数清理（优先文件内 create_time，缺失用 mtime）。
- **远程模式（MES）**：`storage_mode=remote` 时 `send_remote_report` POST 汇总 JSON `{plan, sn, station_id, overall, total, passed, failed, skipped, time, results}`，URL 为 `mes_interface`（http 开头则直接使用）否则 `mes_server + mes_interface`，Basic 认证。
- 单计划配置决定各项开关，互不影响；任一上报失败均记录日志并暂存，不影响本地保存与测试流程。

### 3.7 权限与账号（user_manager.py）

- 两级角色：管理员（全部页面+计划/变量编辑+统计清零）、操作员（仅执行页面）。
- 密码明文存储于 `users.json`（本地单机系统）；`require_login` 即"一键分权"开关：
  - 开：下次启动强制登录；关：直接以管理员身份进入管理页面。
- 默认账号：admin/admin（管理员）、operator/operator（操作员），首次运行自动种子化。

### 3.8 UI 控制器模式

所有页面采用 **"控制器 + UI 宿主"** 模式：

```
class ExecutePage:                      # 控制器（非 QWidget）
    def setup(self, host):              # host 是装载 .ui 的 QWidget
        uic.loadUi(UI_FILES["execute"], host)   # QtUiLoader 加载
        self.ui = host                  # 通过属性访问控件
        ... 信号连接 / 初始化 ...
```

- 控件全部以命名属性访问（`self.ui.xxx`），与业务逻辑完全解耦。
- 管理页面运行时重构 content 区为 `QStackedWidget`，四个子页面（计划/变量/设置/用户）由侧边栏 `navList` 切换；顶部"计划设置"工具栏仅计划页显示。
- **无边框窗口拖拽**：`main_window.py` 安装应用级 `_WindowDragFilter`，在非交互控件上按住左键拖拽可移动窗口；拖动距离超过 `QApplication.startDragDistance()×5` 才生效（避免点击误触），最大化时拖动会先还原为普通窗口再移动。
- **产线触屏 Kiosk 模式**：`main_window.py` 启动即 `Qt.WindowFullScreen` + `FramelessWindowHint` 全屏无边框（系统顶栏与左侧坞自动隐藏，菜单栏隐藏改快捷键：Ctrl+M 管理、Ctrl+Shift+L 重登、Ctrl+Q 退出、F11 全屏切换）；`_kiosk_timer`（800ms）经 `_kiosk_guard` 守护，防止触摸手势把窗口还原/最小化，F11 手动退出后 60 秒内不自动回全屏；底部状态栏（statusBar）显示电池电量/电源与 WiFi 信号强度（`system_status.py` 读 `/sys/class/power_supply`、`/proc/net/wireless`，每 5s 刷新），替代被隐藏的系统状态栏。

## 4. 关键流程时序

### 4.1 启动流程

```
main.py
  └─ QApplication
      └─ main_flow.bootstrap
           ├─ 初始化 4 个共享单例
           ├─ 种子化默认账号
           ├─ register_api(context.build_api())
           ├─ require_login ?
           │    ├─ 是 → LoginDialog（校验账号+角色）→ 按登录角色进 MainWindow
           │    └─ 否 → 以管理员身份进 MainWindow
           └─ MainWindow：菜单栏导航 + QStackedWidget（执行/管理页）
```

### 4.2 单次执行流程

```
点击[开始] → start_run()
   ├─ 校验已加载 PLAN
   ├─ 创建 EngineWorker + 连接全部信号
   ├─ engine.start()（QThread）
   │      └─ run():
   │           ├─ 打开运行日志（RunLogger）并桥接脚本日志到文件
   │           ├─ wait_sn？── 握手等待SN（当前执行页关闭，SN 由脚本 set_sn_to_Panel 输入）
   │           ├─ _login_for_token（启用 Token 认证时先取 Token）
   │           ├─ _retry_pending_uploads（续传上次失败暂存数据）
   │           ├─ 遍历 flatten_cases()（连续模式则轮询多轮）
   │           │    ├─ wait_if_paused / check_stop
   │           │    ├─ _execute_case(尝试 retry+1 次；skip 用例标"跳过"不执行)
   │           │    │    ├─ action   ：线程池执行函数，不判定（dict 返回即结构化结果）
   │           │    │    ├─ delay    ：分片 sleep，响应暂停（按速度系数缩放）
   │           │    │    ├─ pop      ：GUI 弹窗握手取 True/False，可绑定变量
   │           │    │    ├─ measurement：解析参数→执行→绑定变量→阈值判定
   │           │    │    └─ loop     ：读YAML sessions 逐组执行→解析→判定
   │           │    ├─ 更新进度 / 状态 / 日志（信号）
   │           │    └─ 失败策略 pause 则按策略停止执行
   │           ├─ 计算总体结果
   │           ├─ 生成报告与就地上报（本地/远程文件/MES/逐用例 JSON）
   │           └─ sig_run_finished
   └─ 页面：非连续模式记录生产统计（data/stats.ini 当天 total/pass/fail）；连续模式各轮由 sig_round_finished 实时计入，不再重复累计
```

### 4.3 连续测试模式

```
计划勾选连续测试（continuous）→ 同一次 run() 内由引擎自动多轮
   └─ _run_plan() 内层 while 循环：round_no 自增
       ├─ sig_round_started(round_no) → 页面清空日志只显示当前轮
       ├─ 遍历用例执行（照常 pause/stop/pop 控制与 SN 逻辑）
       ├─ 每轮结束 sig_round_finished(ok, round_no)
       │    ├─ 页面实时计入生产统计（data/stats.ini 当天 total/pass/fail）
       │    └─ 引擎为该轮单独生成报告，仅保留最近一轮结果
       └─ 自动继续下一轮，直到手动停止/退出
```

## 6. 并发与稳定性设计对照

| 非功能需求 | 实现方式 |
| --- | --- |
| UI 不阻塞 | 引擎 QThread；外部函数线程池；延时分片响应暂停 |
| 严禁工作线程操作 UI | 信号槽 + LogBridge 队列，全部 UI 更新回到 GUI 线程 |
| 异常不崩溃 | 引擎 run() 顶层 try-except；handler try-except；`_safe_call` 包装脚本调用 |
| 7×24 内存稳定 | 每次运行独立线程池并 shutdown；脚本按 mtime 缓存失效 |
| 暂停/启停实时响应 | threading.Event + 短轮询（≤50ms），延时切片 10ms 检查 |
| 崩溃绝不静默闪退 | main.py 注册 `sys.excepthook`/threading 异常/Qt 消息钩子进系统日志（syslog）；faulthandler 将 SIGSEGV/SIGABRT/SIGBUS 等原生崩溃写入 `data/logs/crash_*.txt`；异常退出留下 `.prev_crash` 崩溃标记，下次启动弹窗提示上次非正常退出 |
